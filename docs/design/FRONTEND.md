## 1. 문서 목적

본 문서는 nSuns Hybrid의 모바일 웹 UI 구조, 사용자 흐름, 화면 구성 및 공통 컴포넌트의 역할을 정의한다.

- Mobile-first 설계 (모바일 조작성 우선, 8장)
- Dark Fitness 디자인
- 라임 그린 Accent
- 운동 중 빠른 조작
- 세트별 기록과 휴식 타이머 통합
- T2/T3 운동 변경 UX
- 운동 기록 잠금 및 운동별 리셋 UX

상세 계산 규칙은 `CALCULATION_RULES.md`, 기능 및 저장 정책은 `FUNCTIONS.md`를 따른다.

## 4. 화면별 기능

### 4.1 Dashboard

목적: 사용자가 오늘 수행할 운동을 빠르게 확인하고 시작한다.

주요 콘텐츠:

- 현재 프로그램명
- 주간 운동 일정
- 오늘의 T1/T2/T3 목록
- 휴식일 표시
- 운동 시작 또는 진행 중 세션으로 복귀

운동일은 월·화·목·금·토이며 수·일은 기본 휴식일이다.

### 4.2 Setup

목적: 최초 운동 기준 중량 등록.

주요 콘텐츠:

- 4대 운동(벤치프레스, 컨벤셔널 데드리프트, 백 스쿼트, OHP) 1RM 직접 입력
- 나머지 T1/T2 운동의 초기 1RM 추천값 검토·확정·수정 (CALCULATION_RULES 3.6)
- T3 작업 중량 입력
- 운동별 중량 증가 단위 (Setup 프로토타입 범위 밖, 후속 결정)
- 최초 TM 계산 결과
- 입력값 검증 및 저장 상태

동일한 `exerciseId`를 사용하는 운동은 하나의 프로필을 공유한다.

추천값은 실제 측정 1RM이 아니며, 직접 입력(측정)·자동 추정·추정값 확정·사용자 수정 상태를 화면에서 구분한다. 상세는 `screens/SETUP.md`를 따른다.

### 4.3 Routine

목적: 사용자가 T2/T3 운동을 변경한다.

주요 콘텐츠:

- 요일별 T1/T2/T3 구성
- T1 고정 표시
- T2/T3 운동 변경 버튼
- 운동 검색 및 선택
- 신규 운동 기준 중량 입력
- 변경된 중량 계산 결과

지원하지 않는 템플릿은 자동 계산을 수행하지 않는다.

진행 중 세션에서 운동을 변경하는 정책은 U-09 확정 전까지 보류한다.

### 4.4 Workout

본 서비스의 핵심 화면.

운동 중 다른 페이지로 이동하지 않고 주요 작업을 수행할 수 있게 설계한다.

구성:

1. 운동 이름 및 T1/T2/T3 표시
2. 운동 진행률
3. 세트 목록
4. 목표 중량과 목표 반복
5. 실제 중량 및 반복 입력
6. 세트 완료 체크박스
7. 휴식 타이머
8. 운동별 리셋
9. 하루 세션 완료

#### 세트 행 구성

각 세트 행에는 다음 정보를 표시한다.

- 세트 번호
- 목표 중량
- 목표 반복 횟수
- 실제 수행 중량 입력
- 실제 반복 횟수 입력
- 완료 체크박스

AMRAP 세트는 일반 세트와 구분되는 텍스트 라벨을 사용한다.

#### 체크박스 동작

- 사용자가 직접 체크한다.
- 완료 전 실제 수행값 수정 가능
- 체크 시 입력값 검증
- 저장 중 상태 표시
- 저장 성공 후 완료 확정 및 잠금
- 개별 체크 해제 금지
- 완료 기록 직접 수정 금지
- 저장 실패 시 완료 상태 확정 금지

체크박스는 시각적인 체크 표시뿐 아니라 터치하기 쉬운 클릭 영역을 제공해야 한다.

#### 현재 세트 표시

세트 기록의 완료 상태를 기준으로 첫 번째 미완료 세트를 현재 세트로 표시하는 방안을 우선한다.

별도 `currentSetIndex` 저장 여부는 데이터 모델 최종 검토 시 결정한다.

#### 운동별 리셋

- T1/T2/T3 중 대상 운동 선택
- 리셋 영향 안내
- 사용자 확인
- 해당 운동의 모든 세트 기록 초기화
- 다른 운동의 기록 유지

리셋 후 목표값은 해당 운동의 세션 시작 스냅샷 기준으로 복원해야 한다.

단, 사용자가 수정한 목표 중량의 복원 정책은 최종 승인 전까지 미확정으로 관리한다.

COMPLETED 및 ABANDONED 세션의 리셋은 U-14/U-15에 따른다.

### 4.5 History

목적: 저장된 세션 결과 조회.

주요 콘텐츠:

- 운동 수행 날짜
- 운동 종목
- 목표 및 실제 수행 기록
- 완료 상태
- 세션별 수행 결과

기존 완료 기록은 직접 수정할 수 없다.

### 4.6 Settings

주요 콘텐츠:

- 운동별 1RM
- 현재 TM 확인
- T3 작업 중량
- 운동별 중량 증가 단위
- T1/T2/T3 기본 휴식 시간
- 로컬 데이터 저장 관련 안내

1RM 수정 시 currentTM 재설정 또는 유지 선택을 제공한다.

## 6. 휴식 타이머 UX

기본 시간:

- T1: 180초
- T2: 120초
- T3: 30초

주요 동작:

- 세트 완료 후 자동 시작
- 일시정지
- 재개
- ±15초 조정
- 건너뛰기
- 시간 종료 상태 표시

타이머는 세트 기록 화면에서 접근 가능해야 한다.

마지막 세트 및 운동 간 전환 시 타이머 동작은 기존 기능 명세와 일치시킨다.

타이머 배치 방식(하단 고정 바 / 카드 / 기타)은 화면 프로토타입 단계에서 결정한다.

## 7. 상태 및 오류 UX

### 7.1 세트 상태

- 미완료
- 저장 중
- 완료 및 잠금
- 저장 실패

### 7.2 운동 세션 상태

- NOT_STARTED
- IN_PROGRESS
- PAUSED
- COMPLETED
- ABANDONED

### 7.3 오류 처리

- 잘못된 중량 및 반복 입력
- 운동 기준 중량 누락
- 미승인 계산 템플릿
- IndexedDB 저장 실패
- 잠금 기록 수정 시도
- 허용되지 않는 리셋 요청

오류 발생 시 작업 결과를 성공으로 표시하지 않는다.

## 8. Mobile First 및 반응형 UX — v0.3 갱신 (STEP 08 추가 요구사항)

nSuns Hybrid는 헬스장에서 스마트폰으로 쓰는 운동 기록 서비스다. **모바일 조작성을 PC보다 우선**하고, 실제 운동 중 흐름(세트 수행 → 기록 → 체크 → 휴식)을 기준으로 설계한다. PC 화면을 줄이기만 한 반응형 구현은 하지 않는다.

### 8.1 지원 환경

| 구분 | 대상 | 검증 너비 |
|---|---|---|
| 모바일 (우선) | iPhone Safari, Android Chrome | 320 / 390 / 430px |
| 태블릿 | iPadOS Safari, Android 태블릿 Chrome | 768 / 1024px |
| PC | Chrome, Safari 최신 버전 | 정상 작동 (최적화 대상 아님) |

### 8.2 운동 중 UX 요구사항

| ID | 요구사항 | 설계 기준 |
|---|---|---|
| M-01 | 모든 핵심 기능은 터치만으로 사용 | hover·키보드 전용 기능 금지, 단축키는 보조 수단 |
| M-02 | 세트 완료 체크 터치 영역 최소 44 × 44px | 모든 버튼·입력·체크박스 동일 |
| M-03 | 중량·반복 입력 시 숫자 키패드 | 중량 `inputMode="decimal"`, 반복 `inputMode="numeric"` |
| M-04 | 확대 없이 기록 | 입력 글자 크기 16px 이상 (iOS Safari 자동 확대 방지), 사용자 확대는 막지 않음 |
| M-05 | 가로 스크롤 없음 | 320px에서 세트 행은 두 줄 배치 (WORKOUT.md 5장) |
| M-06 | 세트 완료 직후 저장 | 체크 → 검증 → 저장 성공 시에만 완료 (FUNCTIONS 9.2.1) |
| M-07 | 저장 실패 시 완료로 표시하지 않음 | 미완료 유지, 입력값 보존, 재시도 |
| M-08 | 스크롤 중에도 휴식 타이머 확인 | 하단 고정 타이머 패널, Safe Area 하단 여백 |
| M-09 | 새로고침 후 기록 유지 | IndexedDB에 저장된 완료 세트·진행 상태 복원 |
| M-10 | 한 손 조작 | 체크박스·주요 버튼은 화면 오른쪽·하단 접근 영역 우선 |

### 8.3 화면 크기별 원칙

- **모바일:** 단일 열, 세트 입력과 체크박스 우선, 보조 정보 최소화.
- **태블릿·PC:** 콘텐츠 최대 너비(현재 프로토타입 480px)로 모바일과 같은 흐름을 유지한다. 세트 표를 가로로 넓히지 않는다. 태블릿 전용 다단 레이아웃은 승인 대기 항목이다 (12장).

### 8.4 데이터 안정성 (모바일 브라우저)

| 항목 | 기준 |
|---|---|
| IndexedDB 호환성 | iOS Safari, Android Chrome 실기기에서 저장·복원·트랜잭션 롤백을 검증한다 |
| 오프라인 기록 접근 | 저장된 기록은 서버 없이 기기 안 IndexedDB에서 읽는다. 단, **앱 화면 자체를 오프라인에서 새로 불러오는 것은 PWA·오프라인 캐싱 도입 전까지 보장되지 않는다** (이미 열린 화면에서는 계속 사용 가능) |
| PWA·오프라인 캐싱 | 별도 후속 단계에서 검토한다 |
| 데이터 삭제 위험 | 브라우저 데이터 삭제, 시크릿 모드, 저장소 정리 정책으로 기록이 사라질 수 있음을 앱 안에서 안내한다 |
| 백업 필요성 | 기기 변경·데이터 삭제 대비 백업(JSON 내보내기 등)이 필요하다. 기능 범위는 별도 요구사항으로 확정한다 |

모바일 UI 구현과 PWA 도입은 후속 단계로 분리한다. 기존 Setup·Workout 프로토타입은 그대로 유지한다.

## 9. 기술 구현 원칙

- Next.js App Router
- React + TypeScript
- Tailwind CSS
- Dexie + IndexedDB
- Zod 입력 검증

UI 컴포넌트에서 TM 및 운동별 중량 계산식을 중복 구현하지 않는다.

저장 작업은 저장 계층을 통한다.

체크박스 완료 상태는 실제 저장 결과와 일치해야 한다.

## 10. 테스트 및 수용 기준

FRONTEND 설계 기준:

- 모바일에서 세트 중량과 반복 횟수가 잘 보인다.
- 각 세트를 체크박스로 완료할 수 있다.
- 저장 성공 후 완료 세트가 잠긴다.
- 저장 실패 시 성공으로 표시하지 않는다.
- 운동 리셋 시 다른 운동 기록이 보존된다.
- T2 운동 변경 후 해당 운동 TM을 사용한다.
- T3는 7세트 × 12회 구조를 유지한다.
- 새로고침 후 저장된 세트 완료 상태가 복원된다.
- 휴식 타이머를 운동 기록 흐름에서 조작할 수 있다.

### 10.1 Mobile First QA 체크리스트 — v0.3 추가

모든 화면은 아래 항목을 통과해야 한다. 자동 검증(Playwright)과 실기기 수동 검증을 구분해 기록하고, 실행하지 못한 항목은 통과로 보고하지 않는다.
