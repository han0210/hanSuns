## 1. 문서 목적

BASE.md는 nSuns Hybrid의 공통 디자인 시스템과
UI/UX 설계 원칙을 정의한다.

모든 화면은 본 문서를 기본 기준으로 개발한다.

화면별 레이아웃과 상세 인터랙션은

CALCULATION_RULES.md 및 FUNCTIONS.md를 따른다.

## 2. 디자인 방향

### 2.1 디자인 콘셉트

Dark Fitness / Minimal / Performance-focused

핵심 키워드:

- Minimal
- Functional
- Focused
- Fast Interaction
- High Readability
- Mobile First

### 2.2 디자인 원칙

1. 운동 중 조작에 집중한다.
2. 정보보다 행동을 우선한다.
3. 불필요한 화면 이동을 줄인다.
4. 목표 중량과 실제 수행 중량을 명확하게 구분한다.
5. 중요한 정보는 시각적 위계로 강조한다.
6. 한 손으로 조작할 수 있도록 설계한다.
7. 애니메이션보다 반응 속도를 우선한다.
8. 일관된 컴포넌트를 재사용한다.

### 2.3 Boostcamp 벤치마킹

참고할 요소:

- 운동 프로그램 중심 탐색 구조
- 세트 단위 운동 기록 UX
- 중량 및 반복 횟수 중심 정보 위계
- 운동 중 휴식 타이머 접근성
- 직관적인 진행 상태 표시
- 모바일 화면에 적합한 입력 인터페이스

그대로 복제하지 않을 요소:

- 브랜드 로고 및 고유 그래픽
- 프로그램 마켓플레이스
- 소셜 및 커뮤니티 UI
- 프리미엄 구독 UI
- 불필요한 운동 분석 기능

nSuns Hybrid는 단일 운동 프로그램에 최적화한다.

## 3. 컬러 시스템

아래 색상은 초기 디자인 제안값이다.
실제 UI 프로토타입 검수 후 최종 승인한다.

### 3.1 기본 컬러

| Token | HEX | 용도 |
|---|---|---|
| background | #101114 | 앱 기본 배경 |
| surface | #1C1F24 | 카드 및 섹션 |
| surfaceElevated | #272B31 | 모달, 입력 영역 |
| border | #363B43 | 경계선 |
| textPrimary | #F3F4F6 | 주요 텍스트 |
| textSecondary | #A3AAB5 | 보조 텍스트 |
| textMuted | #737A84 | 비활성 정보 |
| accent | #B8F15C | 핵심 행동 |
| accentText | #101114 | 강조 배경 위 텍스트 |
| danger | #F87171 | 오류 및 초기화 |
| warning | #FBBF24 | 경고 |
| success | #B8F15C | 완료 상태 |

### 3.2 컬러 사용 원칙

- 기본 배경은 다크 테마를 사용한다.
- 핵심 CTA에만 Accent 컬러를 사용한다.
- 일반 정보 카드에 강조색을 남용하지 않는다.
- 오류와 위험한 작업은 Danger 컬러로 표시한다.
- 상태는 색상뿐 아니라 텍스트 또는 아이콘으로 구분한다.
- 모든 텍스트의 대비는 WCAG AA를 목표로 한다.
- 색상 토큰은 중앙에서 관리하고 임의의 HEX 사용을 지양한다.

## 4. 타이포그래피

### 4.1 Font

기본 글꼴:

Pretendard

Fallback:

- Apple SD Gothic Neo
- system-ui
- sans-serif

숫자 및 중량 표시에는 tabular-nums를 사용한다.

외부 폰트 로딩이 실패해도 시스템 폰트로
정상 표시되어야 한다.

### 4.2 Typography Scale

| Token | Size | Weight | 사용 |
|---|---|---|---|
| display | 28px | 700 | 핵심 운동 중량 |
| h1 | 24px | 700 | 화면 제목 |
| h2 | 20px | 600 | 운동 제목 |
| h3 | 18px | 600 | 카드 제목 |
| body | 16px | 400 | 기본 텍스트 |
| bodyStrong | 16px | 600 | 주요 값 |
| caption | 14px | 400 | 보조 정보 |
| small | 12px | 500 | 라벨 및 메타 정보 |

### 4.3 텍스트 원칙

- 일반 본문은 16px을 기본으로 한다.
- 실제 중량과 반복 횟수는 우선적으로 강조한다.
- 단위(kg, 회)는 숫자와 구분해 표시한다.
- 과도한 Bold 사용을 피한다.
- 긴 설명 대신 간결한 한국어 라벨을 사용한다.

## 5. 레이아웃 시스템

### 5.1 Mobile First

기준 디자인 화면:

- 기본 시안 너비: 390px
- 최소 대응 너비: 320px
- 태블릿/데스크톱: 반응형 확장

390px은 디자인 기준이지 고정 화면 너비가 아니다.

### 5.2 Layout Tokens

| Token | Value |
|---|---|
| pagePadding | 16px |
| sectionGap | 24px |
| cardPadding | 16px |
| cardGap | 12px |
| itemGap | 8px |
| borderRadiusSmall | 8px |
| borderRadiusMedium | 12px |
| borderRadiusLarge | 16px |

간격은 기본적으로 4px 배수로 통일한다.

### 5.3 컨테이너

- 주요 콘텐츠는 단일 열을 기본으로 한다.
- 모바일에서 가로 스크롤을 요구하지 않는다.
- 넓은 화면에서는 콘텐츠 최대 너비를 제한한다.
- 운동 중 주요 조작 버튼이 화면 밖으로 밀리지 않게 한다.
- 하단 고정 UI 사용 시 Safe Area를 고려한다.

## 6. 핵심 컴포넌트

### 6.1 Button

종류:

- Primary
- Secondary
- Ghost
- Danger

공통 규칙:

- 주요 버튼 높이: 48px 이상
- 최소 터치 영역: 44×44px
- 버튼 상태: Default / Pressed / Disabled / Loading
- 한 화면의 핵심 Primary Action은 가급적 하나로 제한한다.

### 6.2 Card

사용 목적:

- 운동 정보
- 중량 요약
- 운동 진행 상태
- 휴식 타이머

스타일:

- Surface 배경
- 12~16px 모서리
- 명확한 내부 간격
- 불필요한 그림자 최소화

### 6.3 Input

주요 입력:

- 1RM
- 작업 중량
- 실제 수행 중량
- 실제 반복 횟수
- 운동별 증가 단위

원칙:

- 숫자 입력에 적합한 모바일 키패드 사용
- 중량과 단위를 함께 표시
- 입력값 검증 오류를 해당 입력란 근처에 표시
- 잘못된 값으로 계산 또는 완료 처리 금지
- 사용자 입력 중 불필요한 전체 화면 리렌더링 방지

### 6.4 Checkbox — 세트 완료

각 세트에 체크박스를 배치한다.

확정 UX 정책:

1. 체크 전에는 실제 수행 기록 입력 가능
2. 사용자 체크 시 입력값 검증
3. 저장 성공 후 완료 상태로 전환
4. 완료한 세트는 잠금 상태
5. 체크박스 개별 해제 불가
6. 기록 수정은 해당 운동 전체 세트 리셋으로만 가능

표시 상태:

- NOT_COMPLETED
- SAVING
- COMPLETED
- ERROR

COMPLETED 상태는 체크 표시와 잠금 상태를
시각적으로 구분 가능하게 표시한다.

저장 실패 시 완료된 것처럼 표시하지 않는다.

### 6.5 Modal / Confirmation Dialog

사용 목적:

- 운동 리셋 확인
- 1RM 변경 후 currentTM 처리 선택
- 중요 작업의 취소 또는 확정

원칙:

- 작업의 영향을 구체적으로 설명
- 취소와 확인 버튼 구분
- 위험한 초기화는 Danger 스타일 사용
- 확인 이전에는 데이터 변경 금지

### 6.6 Rest Timer

휴식 타이머는 운동 중 접근하기 쉬운 위치에 표시한다.

기본값:

- T1: 60초
- T2: 60초
- T3: 30초

지원 조작:

- 일시정지
- 재개
- ±15초
- 건너뛰기

원칙:

- 큰 숫자로 남은 시간 표시
- 버튼이 운동 기록 조작을 방해하지 않도록 설계
- 백그라운드 복귀 시 실제 남은 시간 표시
- 종료 시 명확한 시각적 상태 제공

타이머의 실제 경과 시간 계산 방식은
FUNCTIONS.md와 TECHSTACK.md를 따른다.

## 7. 운동 기록 정보 위계

운동 중 가장 중요한 정보 순서는 다음과 같다.

1. 현재 운동 종목
2. 현재 세트의 목표 중량
3. 목표 반복 횟수
4. 실제 중량 및 반복 입력
5. 세트 완료 체크박스
6. 휴식 타이머
7. 기타 보조 정보

### 7.1 T1 / T2 / T3 구분

각 티어는 명확한 텍스트 라벨로 구분한다.

- T1: Main Lift
- T2: Secondary Lift
- T3: FST-7

티어별로 전혀 다른 화면 스타일을 사용하지 않는다.

공통 컴포넌트를 사용하며
세트 수와 중량 입력 방식만 해당 규칙에 맞게 표현한다.

### 7.2 목표값과 실제값

목표 중량 및 반복 횟수는 자동 계산값이다.

실제 수행 중량과 반복 횟수는 사용자 기록값이다.

두 값은 시각적으로 구분해야 한다.

예시 라벨:

- 목표 60kg × 5회
- 실제 60kg × 5회

## 8. 상태 디자인

### 8.1 운동 상태

- 시작 전
- 진행 중
- 일시 중단
- 완료
- 중도 종료

### 8.2 세트 상태

- 미완료
- 저장 중
- 완료 및 잠금
- 저장 오류

### 8.3 오류 상태

다음 오류를 명확하게 안내한다.

- 기준 중량 미입력
- 허용되지 않는 입력값
- 계산 템플릿 미승인
- 로컬 데이터 저장 실패
- 현재 상태에서 허용되지 않는 기록 수정
- 리셋 불가 상태

미확정 계산 규칙을 임의의 숫자로 대체하지 않는다.

## 9. 모바일 UX 원칙

### 9.1 한 손 조작

- 핵심 입력과 완료 동작은 손이 닿기 쉬운 위치에 배치
- 작은 아이콘만으로 주요 기능 제공 금지
- 터치 영역 간 충분한 간격 확보

### 9.2 최소 인터랙션

- 세트 완료까지 불필요한 단계 최소화
- 운동 기록과 타이머를 연속된 흐름으로 제공
- 주요 작업에 매번 불필요한 확인창 표시 금지
- 데이터 삭제성 작업에만 명확한 확인 절차 적용

### 9.3 시각적 피드백

- 체크박스 저장 중 로딩 상태 표시
- 저장 완료 시 완료 상태 표시
- 오류 발생 시 구체적인 안내
- 짧고 절제된 상태 전환 애니메이션 사용

### 9.4 접근성

- WCAG AA 대비 목표
- 충분한 터치 영역
- 키보드 조작 지원
- 명확한 Focus 상태
- 색상 이외의 완료 상태 표시
- prefers-reduced-motion 지원

## 10. 반응형 설계

### Mobile

- 단일 열 중심
- 세트 기록 및 체크박스 우선
- 불필요한 보조 정보 최소화

- 넓어진 화면에 맞춰 정보 간격 확장
- 운동 기록 중심의 정보 위계 유지

### Desktop

- 지나치게 넓은 기록 테이블 방지
- 콘텐츠 최대 너비 적용
- 모바일과 동일한 핵심 작업 흐름 유지

## 11. 기술 구현 원칙

디자인 시스템은 아래 기술 스택을 기준으로 한다.

- Next.js App Router
- React
- TypeScript
- Tailwind CSS

공통 스타일은 CSS 변수 또는 Tailwind Theme Token으로 관리한다.

권장 컴포넌트:

- Button
- Card
- NumericInput
- SetRow
- CompletionCheckbox
- RestTimer
- ConfirmationDialog
- StatusMessage

컴포넌트는 필요한 시점에 구현한다.

디자인 시스템 문서만으로
화면 또는 새로운 기능 구현을 시작하지 않는다.

## 12. 디자인 금지사항

- Boostcamp의 브랜드 자산을 그대로 복제하지 않는다.
- 과도한 애니메이션을 사용하지 않는다.
- 핵심 중량과 반복 횟수의 가독성을 희생하지 않는다.
- 화면마다 임의의 컬러·간격 값을 만들지 않는다.
- 작은 체크박스만으로 터치 조작을 강제하지 않는다.
- 완료된 기록을 수정 가능한 것처럼 표시하지 않는다.
- 저장 실패를 성공으로 표시하지 않는다.
- 원본 nSuns 계산식이 확정되지 않은 상태에서 가짜 운영 중량을 표시하지 않는다.
