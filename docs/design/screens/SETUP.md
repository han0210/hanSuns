## 1. 화면 목적

처음 사용하는 사용자가 운동별 기준 중량을 한 번에 설정한다.

- 사용자는 4대 운동의 1RM만 직접 입력한다.
- 나머지 T1/T2 운동은 초기 1RM 추천값을 검토해 확정하거나 수정한다.
- T3(FST-7)는 운동별 작업 중량을 직접 입력한다.

추천값은 초기 설정을 돕는 값이며, 실제 측정 1RM이나 원본 nSuns 공식으로 표시하지 않는다.

## 2. 사용자 흐름

| 단계 | 화면 | 다음으로 가는 조건 |
|---|---|---|
| 1 | 4대 운동 1RM 입력 + 초기 TM(90%) 실시간 표시 | 4개 모두 유효 |
| 2 | 나머지 T1/T2 추천값 검토·확정·수정 | 모든 값 유효 |
| 3 | T3 작업 중량 입력 (7 × 12회) | 5개 모두 유효 |
| 4 | 설정 확인 → 확정 → Workout으로 이동 | — |

- 상단에 4단계 진행 표시, 하단에 고정된 `이전` / `다음` 버튼을 둔다.
- `이전`으로 돌아가 기준 1RM을 바꿀 수 있다. 바꾼 값은 2단계 추천값에 즉시 반영된다(자동 추정 상태만).

## 3. 입력 컴포넌트

| 항목 | 규칙 |
|---|---|
| 단위 | kg 고정 표시 |
| 키패드 | 모바일 소수점 숫자 키패드 (`inputMode="decimal"`) |
| 허용 값 | 0보다 큰 숫자 (예: 62.5) |
| 라벨 | 운동 이름 + 사용 요일·티어 |
| 미리보기 | 1RM 입력 즉시 초기 TM 표시. 표시만 소수 둘째 자리, 내부 값은 반올림하지 않음 |
| 덤벨 운동 | 작업 중량은 한 손 기준으로 입력 (양손 합산하지 않음, U-19 확정) |

## 4. 자동 추정값 표시

각 추천 운동 카드에는 다음을 표시한다.

1. 출처 배지: `자동 추정` / `🔒 추정값 확정` / `🔒 사용자 수정`
2. 근거 배지: `Hybrid MVP 추천 비율` (원본 nSuns 공식 비율이 아님)
3. 계산식: 예) `백 스쿼트 120 kg × 80% = 96 kg`
4. 1RM 입력칸 (추천값이 채워진 상태)
5. 초기 TM (90%)

| 운동 | 근거 | 표시 |
|---|---|---|
| 프론트 스쿼트 | 백 스쿼트 × 80% | Hybrid MVP 추천 비율 |
| 바벨 로우 | 데드리프트 × 55% | Hybrid MVP 추천 비율 |
| 인클라인 벤치프레스 | 벤치프레스 × 85% | Hybrid MVP 추천 비율 |
| 바벨 슈러그 | 바벨 로우 기준 1RM × 50% (사용자 확정·수정값 우선) | Hybrid MVP 추천 비율 |
| 스모 데드리프트 | 값 없음 | 원본 검증 대기 · 계산 없음 (U-18) |
| OHP (월 T2) | 1단계 OHP 공통 프로필 | 안내 문구만 표시 |

1RM 출처는 `직접 입력 1RM`과 추정 기반(`자동 추정` / `추정값 확정` / `사용자 수정`)으로 구분한다. `직접 입력`은 사용자가 입력한 값이라는 뜻이며 실제 측정이 검증되었다는 뜻이 아니다. 추정 기반 값은 확정·수정해도 직접 입력으로 표시하지 않는다. 확인 화면의 추정 표 제목에 "측정값 아님"을 표시한다.

## 5. 수정 및 확인 UX

- 입력칸을 수정하면 `사용자 수정` 상태가 된다.
- `이 추정값으로 확정`을 누르면 현재 추천값으로 고정된다.
- `자동 추정값으로 되돌리기`로 자동 추정 상태로 돌아갈 수 있다. 버튼에 현재 추천값을 함께 표시한다.
- 확정·수정한 값은 기준 운동 1RM이 바뀌어도 자동으로 바뀌지 않는다.
- 4단계 확인 화면은 직접 입력, 추정 기반, T3를 표로 보여준다. 자동 추정 상태로 남은 값의 개수를 안내한다.
- `이대로 확정`을 누르면 자동 추정 상태의 값도 그 시점 값으로 확정된다.

## 6. 입력 오류

| 상황 | 처리 |
|---|---|
| 빈 값 | 입력칸을 벗어나거나 `다음`을 누르면 "값을 입력하세요" |
| 0·음수·문자 | "0보다 큰 숫자(kg)를 입력하세요" |
| 유효하지 않은 값으로 `다음` | 단계 이동 차단 + 하단 안내 |
| 추천값 입력칸을 비우거나 잘못 수정 | 해당 카드 오류 표시, 3단계 이동 차단 |

오류는 입력칸 아래에 표시하고 `aria-invalid`, `role="alert"`로 전달한다.

## 7. 모바일 레이아웃

- 기준 390px, 검증 320 / 390 / 430px
- 단일 열 카드, 가로 스크롤 없음
- 모든 버튼·입력 최소 44 × 44px
- 하단 고정 버튼은 Safe Area 하단 여백을 고려한다

Mobile First 요구사항과 QA 체크리스트(768 / 1024px 포함)는 `FRONTEND.md` 8장·10.1절을 따른다.

## 8. 수용 기준

| ID | 시나리오 | 기대 결과 |
|---|---|---|
| S-01 | 4대 운동 1RM 입력 | 초기 TM = 1RM × 90% 즉시 표시 |
| S-02 | 잘못된 값 입력 | 오류 표시, 다음 단계 진행 불가 |
| S-03 | 2단계 진입 | 프론트 스쿼트·로우·인클라인·슈러그 추천값과 근거 배지 표시 |
| S-04 | 추천값 수정 | `사용자 수정` 상태, 이후 기준 변경에도 유지 |
| S-05 | 추천값 확정 | `추정값 확정` 상태, 이후 기준 변경에도 유지 |
| S-06 | 자동 추정 상태에서 기준 변경 | 추천값 재계산 |
| S-07 | T3 작업 중량 입력 | 운동별 독립 값 |
| S-08 | 설정 확정 | 모든 값 고정, Workout으로 이동 가능 |
| S-09 | 320 / 390 / 430px | 가로 스크롤·잘림 없음 |
