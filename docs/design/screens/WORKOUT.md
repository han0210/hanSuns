## 1. 문서 목적

본 문서는 nSuns Hybrid의 운동 수행 화면에 대한 UI/UX 상세 명세를 정의한다.

운동 수행 화면은 전체 세트 리스트형을 사용한다.

사용자는 화면에서 다음 작업을 수행한다.

1. 운동별 전체 세트와 목표 중량 확인
2. 실제 수행 중량 및 반복 횟수 입력
3. 체크박스를 통한 세트 완료
4. 휴식 타이머 확인 및 조작
5. T1/T2/T3 운동 진행 상황 확인
6. 필요한 경우 운동별 전체 세트 리셋
7. 하루 운동 세션 완료

운동 계산식은 `CALCULATION_RULES.md`, 기록 잠금과 저장 규칙은 `FUNCTIONS.md`를 따른다.

## 4. 운동별 섹션

각 운동은 독립된 카드형 섹션으로 표시한다.

운동 섹션은 다음 데이터를 사용한다.

- `sessionExerciseId`
- `exerciseId`
- `tier`
- 운동 이름
- 적용 템플릿 ID 및 버전
- 운동의 세트 목록
- 완료 세트 수
- 전체 세트 수
- 해당 운동의 진행 상태

### 4.1 T1

- Main Lift 라벨
- 고정 운동 종목
- 승인된 T1 템플릿의 목표 중량
- 목표 반복 횟수
- AMRAP 여부
- 수행 기록과 완료 체크박스

### 4.2 T2

- Secondary Lift 라벨
- 사용자 설정 운동 이름
- 선택 운동의 독립적인 기준 중량
- 승인된 운동 유형별 템플릿
- 실제 수행 기록 및 체크박스

진행 중 T2 운동 변경은 U-09 확정 전까지 제공하지 않는다.

### 4.3 T3

- FST-7 라벨
- 7세트 × 12회
- 운동별 작업 중량
- 실제 수행 기록 및 체크박스
- 기본 휴식 30초

T3의 작업 중량은 TM 기반 계산을 사용하지 않는다.

## 5. 세트 리스트

### 5.1 기본 구조

각 세트는 한 개의 독립된 행으로 표시한다.

| 구성 | 표시 내용 |
|---|---|
| Set | 세트 번호 |
| Target | 목표 중량 × 목표 반복 |
| Actual | 실제 중량 및 반복 입력 |
| Complete | 완료 체크박스 |

세트 리스트는 항상 세트 번호 순으로 표시한다.

완료된 세트도 목록에서 삭제하거나 숨기지 않는다.

### 5.2 입력 방식

미완료 세트에서 다음 값을 입력한다.

- 실제 중량
- 실제 반복 횟수

입력 조건:

- 숫자 키패드 제공
- kg 단위 명시
- 반복 횟수는 정수
- 중량은 유효한 숫자
- 입력 누락 또는 오류 시 완료 처리 금지

목표 중량은 자동 계산값을 기본으로 사용한다.

세트 완료 전 목표 중량을 수정할 수 있다는 기존 기능은 유지한다.

### 5.3 AMRAP 세트

AMRAP 세트에는 `AMRAP` 라벨을 표시한다.

예시:

```text
SET 3 · AMRAP

목표: 75kg × 1+
실제: 75kg × [반복 횟수]
```

표시값은 예시이며 실제 중량은 계산 엔진의 승인된 템플릿에서 가져온다.

AMRAP의 반복 횟수 미입력이나 실제 중량 미달은 자동 증량 판정 보류와 연결된다.

## 6. 체크박스 완료 UX

### 6.1 기본 동작

사용자는 각 세트 수행이 끝난 뒤 체크박스를 직접 누른다.

진행 순서:

1. 실제 수행 중량 입력
2. 실제 반복 횟수 입력
3. 체크박스 선택
4. 입력값 검증
5. 저장 요청
6. 저장 성공
7. 완료 및 잠금 상태 표시
8. 필요한 경우 휴식 타이머 시작

### 6.2 체크박스 상태

| 상태 | UI |
|---|---|
| NOT_COMPLETED | 빈 체크박스 |
| SAVING | 로딩 표시, 중복 클릭 방지 |
| COMPLETED | 라임 체크 표시, 잠금 |
| ERROR | 저장 실패 메시지 |

### 6.3 완료 후 잠금

저장 성공 후 완료된 세트는 다음 정책을 적용한다.

- 체크 해제 불가
- 실제 중량 수정 불가
- 실제 반복 횟수 수정 불가
- 해당 세트의 목표 중량 수정 불가
- 일반적인 수정 요청은 저장 계층에서도 거부

완료 기록을 수정하려면 해당 운동 전체 세트 리셋이 필요하다.

### 6.4 저장 실패

IndexedDB 저장에 실패하면 완료 상태를 확정하지 않는다.

- 체크박스는 완료 상태로 변경되지 않는다.
- 사용자가 입력한 값은 화면에 유지한다.
- 오류 메시지를 표시한다.
- 사용자는 저장을 다시 시도할 수 있다.

실패한 기록에 대해 휴식 타이머나 증량 처리를 성공한 것처럼 실행하지 않는다.

## 7. 운동 진행률

### 7.1 운동별 진행률

```text
completedSets / totalSets
```

완료 세트 수는 저장된 완료 기록을 기준으로 계산한다.

### 7.2 전체 진행률

T1/T2/T3의 세트 수를 합산하여 표시한다.

```text
전체 완료 세트 수 / 전체 목표 세트 수
```

### 7.3 현재 세트

첫 번째 미완료 세트를 기본 현재 세트로 표시한다.

별도 현재 세트 인덱스를 저장하지 않는 방안을 우선한다.

다만 사용자가 세트를 순서와 다르게 완료할 수 있는지 여부는 미확정으로 남긴다.

## 8. 휴식 타이머

### 8.1 기본 시간

| 운동 | 기본 휴식 |
|---|---|
| T1 | 180초 |
| T2 | 120초 |
| T3 | 30초 |

### 8.2 UX

휴식 타이머는 운동 기록 화면에서 바로 조작할 수 있어야 한다.

권장 배치:

- 화면 하단 고정 패널
- 현재 휴식 시간 표시
- 일시정지·재개 버튼
- ±15초 버튼
- 건너뛰기 버튼

세트 기록을 확인하는 동안 타이머가 화면 전체를 가리지 않도록 한다.

### 8.3 동작 원칙

- 세트 저장 성공 후 필요 시 자동 시작
- 실제 경과 시간을 기준으로 표시
- 백그라운드 복귀 시 남은 시간 재계산
- 타이머 종료 시 시각적 알림
- 소리·진동은 브라우저 지원 범위에서만 제공

운동 간 전환 및 마지막 세트 휴식 규칙은 FUNCTIONS.md에 따른다.

## 9. 운동별 전체 세트 리셋

### 9.1 리셋 범위

리셋은 `sessionExerciseId` 기준으로 수행한다.

선택한 운동의 모든 세트를 초기화한다.

다른 T1/T2/T3 운동의 기록은 유지한다.

### 9.2 리셋 버튼

각 운동 섹션 하단에 보조 위험 액션으로 표시한다.

권장 라벨:

`이 운동 기록 리셋`

### 9.3 확인창

사용자가 리셋 버튼을 누르면 확인창을 표시한다.

제목:

`운동 기록을 리셋할까요?`

설명:

`이 운동의 모든 세트 기록이 초기화됩니다. 처음부터 다시 입력해야 합니다.`

버튼:

- 취소
- 전체 세트 리셋

### 9.4 리셋 이후

- 해당 운동의 실제 기록 초기화
- 완료 체크박스 초기화
- 첫 미완료 세트로 이동
- 다른 운동 기록 유지
- 당시 템플릿과 TM 스냅샷 유지
- 현재 TM 및 증량 이력 변경 금지

목표 중량을 초기 스냅샷으로 되돌리는 권고안은 최종 정책 승인 전까지 미확정으로 관리한다.

### 9.5 리셋 제한

하루 세션 상태가 다음 중 하나일 때만 허용한다.

- IN_PROGRESS
- PAUSED

다음 상태에서는 리셋을 제공하지 않는다.

- COMPLETED
- ABANDONED

완료 및 중도 종료 세션의 리셋은 U-14/U-15 확정 후 재검토한다.

## 10. 하루 운동 완료

사용자가 하루 운동을 모두 수행한 뒤 세션 완료를 선택한다.

권장 버튼:

`오늘 운동 완료`

완료 조건과 누락 세트 처리 방식은 FUNCTIONS.md에 따른다.

완료 시:

- 세션 완료 요청
- 저장 결과 확인
- 승인된 규칙에 따라 T1/T3 증량 판정
- 결과 화면으로 전환

T1 AMRAP 증량값은 검증 전까지 임의 계산하지 않는다.

T3 자동 증량의 정확한 실행 시점은 관련 명세와 최종 정합성 확인이 필요하다.

## 12. 반응형 설계

### 12.1 모바일

기본 기준 너비: 390px

- 단일 열 레이아웃
- 운동별 카드 배치
- 전체 세트 리스트 표시
- 최소 터치 영역 44×44px
- 숫자 입력과 체크박스 간 충분한 간격
- 하단 타이머의 Safe Area 대응

320px 화면에서도 주요 입력과 체크박스가 잘리지 않아야 한다.

Mobile First 요구사항과 QA 체크리스트는 `FRONTEND.md` 8장·10.1절을 따른다.

### 12.2 태블릿 및 데스크톱

- 메인 콘텐츠 최대 너비 제한
- 전체 세트 리스트 유지
- 지나치게 긴 입력 행 방지
- 핵심 운동 정보 위계 유지

## 13. 접근성

- 체크박스에 세트 번호를 포함한 접근성 라벨 제공
- 키보드 조작 및 Focus 표시 지원
- 상태를 색상만으로 구분하지 않음
- 오류 입력에 명확한 설명 표시
- WCAG AA 대비 목표
- Reduced Motion 설정 존중
- 완료·저장 오류 알림에 적절한 상태 전달

## 15. 데이터 연결 원칙

UI는 계산식과 IndexedDB 접근을 직접 구현하지 않는다.

데이터 흐름:

```text
운동 세트 데이터 조회
       ↓
세트 리스트 렌더링
       ↓
사용자 수행값 입력
       ↓
완료 체크박스 선택
       ↓
입력값 검증
       ↓
저장 계층 호출
       ↓
Dexie 저장 성공
       ↓
완료 및 잠금 표시
       ↓
휴식 타이머 시작
```

운동별 리셋은 별도의 저장 작업으로 처리한다.

이미 완료된 기록을 임의로 수정하거나 다른 운동의 데이터에 영향을 주어서는 안 된다.

## 16. 테스트 및 수용 기준

| ID | 시나리오 | 기대 결과 |
|---|---|---|

| W-08 | 운동별 리셋 | 해당 운동만 초기화 |

| W-13 | 미승인 계산 템플릿 | 임의 중량 미표시 |
| W-14 | 작은 모바일 화면 | 가로 잘림 없이 조작 가능 |
| W-15 | 세션 완료 | 기록 저장 및 결과 연결 |

## 17. 구현 금지사항

- 검증되지 않은 nSuns 비율 하드코딩 금지
- 완료 세트의 개별 수정 기능 추가 금지
- 개별 체크박스 해제 기능 추가 금지
- 하루 세션 전체 리셋으로 대체 금지
- 저장 실패 상태를 완료로 표시 금지
- 임의의 TM 증량 로직 추가 금지
- 사용자 승인 없이 진행 중 T2 변경 허용 금지
- Boostcamp 고유 브랜드 자산 복제 금지
- 요청하지 않은 새로운 MVP 기능 추가 금지
