## 1. 기능 명세 개요

### 1.1 서비스 핵심 기능

nSuns Hybrid는 근력 훈련 프로그램 nSuns와 FST-7을 결합한 5일 운동 프로그램이다.

핵심 차별화는 **운동 종목 변경에 따른 자동 중량 스케일링**이다.

사용자가 운동별 1RM 또는 작업 중량을 입력하면 시스템이 해당 운동의 세트별 목표 중량을 자동으로 계산한다.

### 1.2 확정된 계산 원칙

| 항목 | 확정 설정 |
|---|---|
| T1 기준 중량 | 사용자 입력 1RM |
| T2 기준 중량 | 사용자 입력 1RM |
| Training Max | 초기 TM = 1RM × 0.9, 현재 TM(currentTM)은 별도 저장·관리 |
| TM 공유 | 동일 exerciseId는 T1·T2에서 하나의 프로필과 currentTM 공유 |
| T1 바벨 로우 | 일반 5/3/1 벤치형 T1 템플릿 재사용 |
| T2 중량 | 운동별 currentTM × 운동 유형별 T2 템플릿 비율 |
| T3 | FST-7, 12회 × 7세트 |
| T3 시작 중량 | 사용자 입력 작업 중량 |
| T3 증량 | 7세트 모두 12회 이상 + 목표 중량 이상 수행 시 다음 세션 한 단계 증량 |
| 중량 단위 | 운동별 사용자 설정 |
| 반올림 | 최종 세트 중량만, 가장 가까운 단위, 정확한 중간값은 높은 중량 |
| 기록 저장 | 회원가입 없는 브라우저 로컬 저장 |
| 휴식 타이머 | T1·T2·T3 60초 |

## 2. 기본 프로그램

### 2.1 주간 스케줄

| 요일 | T1 | T2 | T3 |
|---|---|---|---|
| 월 | 벤치프레스 | OHP | 케이블 플라이 |
| 화 | 데드리프트 | 프론트 스쿼트 | 레그 컬 |
| 수 | 휴식 | — | — |
| 목 | 스쿼트 | 스모 데드리프트 | 레그 익스텐션 |
| 금 | OHP | 인클라인 벤치프레스 | 덤벨 사이드 레터럴 레이즈 |
| 토 | 바벨 로우 | 슈러그 | 랫풀다운 |
| 일 | 휴식 | — | — |

**운동일 표시 (v1.15, 사용자 결정):** 앱 화면은 요일 대신 **Day 1~5**로 표시하고 실제 요일과 연동하지 않는다. Day 1=월, Day 2=화, Day 3=목, Day 4=금, Day 5=토 구성이며, 저장값(`WorkoutSession.scheduledDay`)은 기존 데이터 호환을 위해 MONDAY~SATURDAY 키를 그대로 쓴다.

**다음 운동일:** 운동 시작 화면은 마지막으로 완료(COMPLETED)한 세션의 다음 Day를 기본 선택한다(Day 5 다음은 Day 1). 완료 기록이 없으면 Day 1. 오늘 날짜·요일은 보지 않으며, 사용자는 다른 Day를 직접 고를 수 있다. 이전 버전의 T3 전용 세션도 완료 세션으로 계산한다.

### 2.2 프로그램 운영

- T1은 기본 요일별 운동 유지
- T2와 T3는 운동 변경 가능
- 운동 변경 시 이전 운동 기록 보존
- 각 운동은 독립적인 기준 중량 보유
- 수요일과 일요일은 기본 휴식일
- 운동 주차와 실제 수행 날짜를 별도로 관리
- 본 프로그램은 원본 nSuns가 아닌 Hybrid 변형 프로그램임을 표시

## 3. FR-001 — 운동별 중량 입력 및 관리

**우선순위:** P0

### 3.1 입력 구조

T1·T2와 T3의 입력 방식을 구분한다.

| 항목 | T1·T2 | T3 |
|---|---|---|
| 최초 입력 | 1RM | 작업 중량 |
| TM 계산 | 적용 | 미적용 |
| 운동별 저장 | 필수 | 필수 |
| 사용자 수정 | 가능 | 가능 |
| 이전 기록 재사용 | 가능 | 가능 |

### 3.2 Training Max 계산

공식:

`initialTM = 1RM × 0.9`

예시:

- 입력 1RM: 100kg
- 계산된 초기 TM: 90kg

TM은 두 값으로 구분한다.

| 값 | 의미 |
|---|---|
| initialTM | 1RM 입력 시 계산되는 초기 TM (1RM에서 재계산 가능한 파생값) |
| currentTM | 다음 세션 계산에 쓰는 현재 TM. 최초에는 initialTM과 같고, AMRAP 증량 후에는 1RM에서 재계산할 수 없으므로 별도 저장한다 |

TM(initialTM·currentTM)은 반올림하지 않고 내부 정밀도를 유지한다. 반올림은 최종 세트 목표 중량에만 적용한다.

1RM 수정 시 currentTM 처리 방식은 미확정이며(CALCULATION_RULES U-05), 사용자 확인 없이 암묵적으로 초기화하지 않는다.

### 3.2.1 동일 운동의 TM 공유

T1과 T2에서 같은 exerciseId를 사용하면 하나의 운동 프로필(input1RM, currentTM)을 공유한다.

- 예: 월요일 T2 OHP와 금요일 T1 OHP는 같은 OHP 프로필을 참조한다.
- 서로 다른 exerciseId는 1RM·TM을 독립적으로 유지한다.
- TM은 공유하지만 세트 템플릿은 T1·T2 각각 별도로 적용한다.
- T1 AMRAP 증량은 승인된 규칙에 따라 공통 currentTM에 반영하며, T2에서 별도 중복 증량하지 않는다.
- 운동 기록은 날짜·세션·티어별로 독립 보존한다.

### 3.2.2 TM 변경 이력

currentTM이 바뀔 때마다 변경 전·후 값, 사유(INITIAL / AMRAP_PROGRESSION / USER_RESET), 근거 세션, 근거 티어, 적용 규칙 ID·버전, 적용 시각을 이력으로 저장한다.

### 3.3 필수 검증

- 1RM은 0보다 커야 한다.
- 입력 단위는 kg을 기본으로 한다.
- 숫자가 아닌 입력은 거부한다.
- 미입력 상태에서는 목표 중량을 생성하지 않는다.
- 계산 시 비정상적으로 높은 수치에 대한 확인 절차를 제공한다.
- 사용자 입력값과 자동 계산값을 별도로 저장한다.

### 3.4 최초 설정 (Setup) — v1.5 추가

화면 상세는 `docs/design/screens/SETUP.md`, 추정 규칙은 `CALCULATION_RULES.md` 3.6절(H-15)을 따른다.

**흐름:** 4대 운동 1RM 입력 → 초기 TM 미리보기 → 나머지 T1/T2 추천값 검토·수정 → T3 작업 중량 입력 → 확인 → 확정

| 구분 | 운동 | 입력 방식 |
|---|---|---|
| 직접 입력 | 벤치프레스, 컨벤셔널 데드리프트, 백 스쿼트, OHP | 1RM 필수 입력 |
| 추천값 | 프론트 스쿼트(×0.80), 바벨 로우(×0.55), 인클라인 벤치프레스(×0.85), 바벨 슈러그(로우 ×0.50), 스모 데드리프트(컨벤셔널 데드리프트 ×0.50, H-19) | 승인된 MVP 초기 추천값을 확정 또는 수정. 초기 TM = 확정 1RM × 0.90 |
| 공통 프로필 | OHP (월 T2) | 직접 입력한 OHP 프로필 사용 (3.2.1) |
| T3 | 케이블 플라이, 레그 컬, 레그 익스텐션, 덤벨 사이드 레터럴 레이즈, 랫풀다운 | 작업 중량 직접 입력 |

규칙:

- 추천값은 확정 전까지 계산에 쓰지 않는다. 확정하면 해당 운동의 `oneRepMax`이 된다.
- 사용자가 확정하거나 수정한 값은 기준 운동 1RM이 바뀌어도 자동으로 바꾸지 않는다.
- 스모 데드리프트(H-19, v1.13): 추정값은 측정 1RM이 아니며 원본 nSuns 공식이 아니다. 스모는 자체 프로필·TM을 가지며, 세트별 반복·TM 비율은 T2 템플릿 정책(U-08)을 따른다(아직 계산하지 않음).
- 스모 도입 전에 설정을 저장한 사용자는 `/setup`에서 스모 값만 추가로 확정·수정해 저장한다(`addSetupExercises`). 기존 설정값·TM 이력·운동 기록은 바뀌지 않으며, 추가 전에도 T3 운동 기록은 계속할 수 있다.
- 직접 입력 1RM(`DIRECT`)과 추정 기반 1RM(자동 추정·추정값 확정·사용자 수정)의 출처를 구분한다. 확정하거나 수정해도 `DIRECT`로 바꾸지 않는다.
- `DIRECT`는 사용자가 1RM을 직접 입력했다는 뜻이며, 실제 측정이 검증되었다는 뜻이 아니다.
- 추천 비율은 nSuns Hybrid MVP 초기 추천값이며 원본 nSuns 공식 환산 비율로 표시하지 않는다.
- 입력값은 0보다 큰 숫자만 허용하며, 유효하지 않으면 다음 단계로 진행할 수 없다.

**데이터 모델 (v1.7 반영, `docs/architecture/DATAMODEL.md`):** 1RM 출처를 구분하기 위해 ExerciseProfile에 다음 두 필드를 둔다. 추천값 자체는 기준 1RM과 비율로 다시 계산할 수 있으므로 저장하지 않는다. TypeScript 필드 이름은 camelCase(`oneRepMaxSource`, `estimateRuleId`)다.

| 필드 | 값 | 목적 |
|---|---|---|
| `oneRepMaxSource` | `DIRECT` / `ESTIMATE_ACCEPTED` / `USER_EDITED` | 직접 입력·추천값 확정·사용자 수정 구분. `DIRECT`는 측정 검증을 뜻하지 않으며, 추정 기반 값은 확정·수정 후에도 `DIRECT`가 되지 않음 |
| `estimateRuleId` | 규칙 ID 또는 null | 추천값을 만든 규칙 추적 (Mock 규칙 여부 판단) |

## 4. FR-002 — T1 자동 중량 계산

**우선순위:** P0

### 4.1 기본 계산

T1은 사용자의 TM과 선택된 nSuns 세트 템플릿을 활용한다.

`목표 중량 = TM × 세트별 강도 비율`

최종 목표 중량은 해당 운동의 설정된 중량 단위에 맞춰 반올림한다.

### 4.2 세트 템플릿 구조

각 템플릿은 아래 정보를 가진다.

| 필드 | 설명 |
|---|---|
| templateId | 템플릿 식별자 |
| setNumber | 세트 순서 |
| targetReps | 목표 반복 횟수 |
| intensityRatio | TM 대비 강도 |
| isAmrap | AMRAP 여부 |
| restSeconds | 기본 휴식 시간 |

**Hybrid 자체 T1 템플릿 (v1.14, CALCULATION_RULES H-20):** 원본 nSuns에서 착안한 Hybrid MVP 자체 템플릿이며 원본 nSuns 공식 템플릿이 아니다. 모든 요일의 T1에 같은 템플릿을 쓴다.

| 세트 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| TM 비율 | 65% | 75% | 85% | 90% | 95% | 90% | 85% | 80% | 75% |
| 목표 반복 | 8 | 6 | 4 | 2 | **1+** | 3 | 5 | 7 | **4+** |

- 목표 중량 = `roundToIncrement(TM × 비율)`. TM은 반올림하지 않은 세션 시작 스냅샷.
- 5·9세트는 AMRAP: 표시된 반복은 최소 반복이며, 실제 반복을 입력해 기록한다.
- T1 자동 TM 증량은 구현하지 않는다(4.4).

### 4.3 바벨 로우 처리

바벨 로우는 일반 5/3/1 벤치형 T1 템플릿을 재사용한다. (v1.14: MVP는 모든 T1이 Hybrid T1 템플릿을 쓰므로 바벨 로우도 같은 템플릿을 쓴다.)

- 바벨 로우 전용 1RM 저장
- TM 90% 계산
- 벤치형 T1 템플릿의 세트·반복·강도 비율 적용
- 운동별 기준 중량과 증량 이력 독립 관리

**주의:** 바벨 로우의 원본 nSuns 템플릿은 존재하지 않는다. 기존 템플릿을 적용하는 것은 nSuns Hybrid의 사용자 정의 규칙이다.

벤치형 템플릿의 정확한 원본 세트 데이터와 템플릿 ID는 원본 검증 후 등록한다.

### 4.4 AMRAP

**v1.16 — T1·T2 TM 증량 (nSuns Hybrid 자체 정책, CALCULATION_RULES H-22):** 운동의 모든 예정 세트가 완료되고 실제 중량 ≥ 목표 중량, 실제 반복 ≥ 목표 반복(AMRAP은 최소 반복)이면, 하루 세션 정상 완료 시 다음 세션부터 currentTM을 올린다. 한 세트라도 미달이면 유지한다.

| 운동 (exerciseId) | 다음 세션 TM 증량 |
|---|---|
| 벤치프레스 (`bench_press`) | +2.5kg |
| OHP (`ohp`) | +2.5kg |
| 바벨 로우 (`barbell_row`) | +2.5kg |
| 백 스쿼트 (`squat`) | +5kg |
| 컨벤셔널 데드리프트 (`deadlift`) | +5kg |
| 그 외 (프론트 스쿼트·스모 데드리프트·인클라인 벤치프레스·바벨 슈러그) | 증량값 확정 전 자동 증량 없음 (TM 유지) |

- 증량은 1RM이 아니라 currentTM에 더하고 TMChange(`SESSION_PROGRESSION`)를 남긴다. 현재·과거 세션의 TM 스냅샷과 목표 중량은 바뀌지 않는다.
- 같은 세션에 같은 운동이 T1·T2로 함께 있으면 한 번만 증량한다. 서로 다른 세션의 증량(예: Day 1 T2 OHP, Day 4 T1 OHP)은 각각 적용된다.
- lb 프로필은 단위 정책 확정 전 자동 증량하지 않는다.
- 아래 원래 항목 중 "원본 nSuns 증량 범위 내 고정값" 설명은 v1.16부터 쓰지 않는다.

- AMRAP 세트는 별도로 표시한다.
- 사용자가 실제 반복 횟수를 입력한다.
- 다음 훈련의 TM 조정에 사용할 수 있도록 기록한다.
- 증량 방식은 원본 nSuns 증량 범위 내 고정값으로 확정했으나, 구체적인 값은 원본 검증 후 확정한다.
- 검증 전에는 임의의 자동 증량 규칙을 적용하지 않는다.
- 증량은 운동 프로필의 공통 currentTM에 반영하고 TM 변경 이력을 남긴다.
- 같은 세션의 완료 처리가 중복되어도 증량은 한 번만 적용한다.

## 5. FR-003 — T2 운동 커스터마이징

**우선순위:** P0

### 5.1 사용자 기능

사용자는 각 요일의 T2 운동을 다른 운동으로 변경할 수 있다.

운동 변경 과정:

1. T2 운동 변경 선택
2. 새 운동 검색 및 선택
3. 저장된 1RM 조회
4. 기존 값이 없으면 1RM 입력
5. 해당 운동 프로필의 currentTM 조회 (신규 입력 시 initialTM 계산)
6. 운동 유형별 T2 템플릿 적용
7. 전체 세트 목표 중량 자동 재계산
8. 변경 내용 저장

### 5.2 핵심 계산

`T2 계산 TM = 선택한 운동 프로필의 currentTM` (최초 입력 시 `1RM × 0.9`)

`세트별 목표 중량 = roundToIncrement(currentTM × 해당 세트 강도 비율)`

**Hybrid 자체 T2 템플릿 (v1.14, CALCULATION_RULES H-21):** 원본 nSuns 공식 템플릿이 아니다. 모든 요일의 T2(스모 데드리프트 포함)에 같은 템플릿을 쓴다. AMRAP 없음, 자동 TM 증량 없음.

| 세트 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| TM 비율 | 50% | 60% | 70% | 70% | 70% | 70% | 70% | 70% |
| 목표 반복 | 5 | 5 | 3 | 5 | 7 | 4 | 6 | 8 |

같은 exerciseId를 T1에서도 사용하면 T1과 같은 currentTM을 참조한다.

### 5.3 필수 조건

- 이전 운동의 1RM을 새 운동에 자동으로 복사하지 않는다.
- 변경 운동의 기존 기준 중량을 우선 사용한다.
- 중량이 없는 운동은 최초 입력을 요청한다.
- 변경 즉시 전체 세트 중량을 재계산한다.
- 이전 운동의 수행 기록은 삭제하지 않는다.
- T2의 세트별 반복·비율은 Hybrid 자체 T2 템플릿을 사용한다 (v1.14). 운동 유형별 템플릿 구분은 후속 검토.
- 지원 템플릿이 없는 운동은 임의 비율을 적용하지 않고 지원 제한을 안내한다.
- T2 자동 증량 (v1.16): H-22 증량값이 있는 운동(현재 OHP)만 목표 달성 시 증량한다. 프론트 스쿼트·스모 데드리프트·인클라인 벤치프레스·바벨 슈러그는 증량값 확정 전까지 TM을 유지한다.

### 5.4 자동 스케일링 예시

예시 조건:

- 기존 운동 A의 TM: 70kg
- 변경 운동 B의 TM: 80kg
- T2 특정 세트 강도: 75%

계산:

- 운동 A: 70 × 0.75 = 52.5kg
- 운동 B: 80 × 0.75 = 60kg

해당 예시는 계산 구조를 보여주기 위한 것이며, 실제 T2 템플릿을 확정한 값은 아니다.

### 6.2 중량 설정

T3는 1RM 대신 작업 중량을 입력한다.

새 운동을 선택하면 이전 작업 중량이 있는지 확인하고, 없으면 사용자에게 입력을 요청한다.

저장된 작업 중량을 기본값으로 7세트에 적용한다.

운동 중 사용자는 **세트 완료 전**에 특정 세트의 목표 또는 실제 수행 중량을 수정할 수 있다. 완료된 세트는 수정할 수 없다(9.2절).

### 6.3 자동 증량

다음 조건을 모두 충족할 때 다음 세션에 한 단계 증량한다.

- 7세트 모두 완료
- 각 세트의 실제 반복 횟수가 12회 이상
- 실제 사용한 중량이 확인됨
- 수행 중량이 목표 작업 중량 이상임

**다음 목표 중량 = 현재 기준 작업 중량 + 종목별 증량 단위**

한 세트라도 목표를 충족하지 못하면 기본적으로 중량을 유지한다.

반복적인 미달이나 감량 필요 여부는 별도 확장 규칙으로 검토한다.

증량은 다음 세션에 적용하며 완료된 과거 세트 기록은 변경하지 않는다.

같은 세션의 완료 처리가 중복되어도 증량은 한 번만 적용한다.

### 6.4 운동 변경 시 처리

운동 종목을 변경하더라도 12회 × 7세트는 유지한다.

새 운동의 저장된 작업 중량을 조회하고, 존재하지 않으면 사용자 입력을 받는다.

종목별 증량 이력은 독립적으로 관리한다.

## 7. FR-005 — 운동별 중량 단위

**우선순위:** P0

### 7.1 기본 설계

사용자가 운동별 중량 증가 단위를 지정할 수 있다.

예시:

| 운동 장비 | 단위 예시 |
|---|---|
| 바벨 | 2.5kg |
| 덤벨 | 한 손 기준 1kg 또는 2kg |
| 머신 | 2.5kg 또는 5kg |

기본값은 초기 제안값이며 사용자가 수정할 수 있다.

### 7.2 반올림 규칙

기본 계산식:

`표시 중량 = round(목표 중량 / 설정 단위) × 설정 단위`

- 양수 중량 기준 가장 가까운 사용 가능 중량을 선택한다.
- 정확히 두 단계의 중간값이면 높은 중량을 선택한다. 예: 61.25kg, 단위 2.5kg → 62.5kg
- JavaScript 부동소수점 오차로 중간값 판정이 뒤바뀌지 않도록 처리한다.
- 반올림은 최종 세트 목표 중량에만 적용하며, 사용자는 실제 수행 중량을 수동 수정할 수 있다.

### 7.3 검증 기준

- 증량 단위는 0보다 커야 한다.
- 중량 단위 변경 시 목표 중량을 다시 계산한다.
- 덤벨 운동 중량은 kg·lb 모두 **한 손 기준**으로 입력·표시·저장하며 양손 중량을 합산하지 않는다. 모든 덤벨 운동에 동일하게 적용한다 (U-19 확정, CALCULATION_RULES H-16). 화면에는 "한 손 기준"임을 표시한다.
- 머신의 중량 표기는 실제 장비와 다를 수 있음을 안내한다.

## 9. FR-007 — 운동 수행 기록

**우선순위:** P0

### 9.1 세트별 기록

각 세트는 다음 정보를 저장한다.

| 필드 | 설명 |
|---|---|
| sessionExerciseId | 소속 운동 실행 단위 ID (SessionExercise) |
| sessionId | 운동 세션 ID (조회 편의용, SessionExercise와 일치해야 함) |
| exerciseId | 운동 ID |
| tier | T1, T2, T3 |
| setNumber | 세트 번호 |
| targetWeight | 목표 중량 |
| actualWeight | 실제 중량 |
| targetReps | 목표 반복 |
| actualReps | 실제 반복 |
| completed | 완료 여부 |
| completedAt | 완료 시각 |

### 9.2 기록 규칙

- 세트별 목표값과 실제 수행값 구분
- 세트 완료 전에는 입력값 수정 가능
- 세트 완료는 사용자가 세트별 체크박스를 직접 체크해 확정한다
- 세트 완료 후에는 해당 세트 기록 잠금 (수정 불가, 체크박스 개별 해제 불가)
- 완료된 세션의 기록은 개별 수정 불가
- 기록을 고치려면 해당 운동의 전체 세트를 리셋 (9.4절)
- 과거 기록 보존
- 운동 종목 변경 시 이전 기록 유지
- 완료된 운동은 이전 기록으로 조회 가능

### 9.2.1 세트 완료 체크 흐름

| 단계 | 처리 |
|---|---|
| 1. 입력 | 체크 전에는 `actualWeight`, `actualReps`를 자유롭게 수정 |
| 2. 체크 | 사용자가 세트 완료 후 체크박스를 직접 체크 |
| 3. 검증 | `actualWeight`: 0보다 큰 유한한 숫자 / `actualReps`: 0 이상의 정수 / 누락 시 체크 거부 |
| 4. 저장 중 | 체크박스는 "저장 중" 상태로 표시, 해당 세트의 입력·체크 중복 조작 차단 |
| 5. 저장 성공 | `completed = true`, `completedAt` 기록 → 세트 잠금 → 체크 표시 확정 |
| 6. 후속 처리 | 같은 운동에 완료되지 않은 세트가 남아 있으면 휴식 타이머 자동 시작, 현재 세트 표시 갱신 |
| 저장 실패 | 체크되지 않은 상태로 되돌림, 입력값 보존, 오류 안내, 재시도 가능, 타이머 시작하지 않음 |

- **완료의 기준은 저장 성공이다.** 화면에서 먼저 완료로 표시한 뒤 저장하는 방식(낙관적 갱신)은 사용하지 않는다.
- 완료된 체크박스는 개별 해제할 수 없다. 기록을 고치려면 해당 운동의 전체 세트를 리셋한다(9.4절).
- 체크는 하루 세션이 IN_PROGRESS일 때 가능하다.
- **현재 세트**는 저장하지 않고 `completed = false`인 첫 세트(가장 작은 `setNumber`)로 계산한다. 모든 세트가 완료되면 현재 세트는 없다.
- 미완료 세트의 입력 중인 값(체크 전 초안)의 저장 여부는 기존 FUNCTIONS 10.3 "운동 중 기록이 변경되면 저장한다"를 따르되, 초안 저장은 `completed`를 바꾸지 않는다.

### 9.2.2 실제값 입력 UX (v1.17)

| 항목 | 동작 |
|---|---|
| 초기값 | 미완료 세트의 실제 중량 = 그 세트의 목표 중량(`manualTargetWeight` 우선), 실제 반복 = 그 세트의 목표 반복. AMRAP은 최소 반복(예: `1+` → 1). 다음 세트는 이전 세트의 기록이 아니라 **자기 목표값**으로 시작한다 |
| 저장된 초안 | 미완료 세트에 저장된 `actualWeight`·`actualReps`가 있으면 목표값 대신 그 값을 표시한다(새로고침·재방문 복원) |
| ± 버튼 | 중량 kg 운동은 2.5kg, 반복은 1회씩. 0 아래로 내려가지 않는다. 숫자가 아닌 값에서 누르면 목표값으로 되돌린다 |
| 직접 입력 | 숫자 키패드로 직접 입력 가능. 검증은 기존 9.2.1 3단계(체크 시)를 그대로 따른다 |
| 완료 | 값을 바꿔도 미완료 상태 유지. 사용자가 체크박스를 눌러 저장에 성공해야 완료·잠금. 목표값 그대로라면 체크 한 번으로 완료 |
| 잠금 | 완료 세트는 입력칸·± 버튼이 사라지고 개별 수정 불가(리셋만 가능, 9.4절) |
| 단위 | 세트(SessionExercise)의 `weightUnit`으로 저장한다. kg·lb를 섞지 않는다. lb 운동의 ± 단위는 운동 프로필의 증가 단위를 쓴다(lb는 U-20 미확정으로 현재 화면에서 만들 수 없음) |

- **초안 저장:** 입력이 멈추고 400ms 뒤 `updateSetDraft()`로 저장한다. 화면이 숨겨지거나(`visibilitychange`) 페이지를 떠날 때(`pagehide`)·화면 해제 시 대기 중인 초안을 즉시 저장한다. 체크 시에는 대기 중인 초안 저장을 취소하고 `completeSet()`으로 저장한다.
- 초안 값이 유효하지 않으면(중량 0 이하·빈 값, 반복 비정수) 그 필드는 `null`로 저장한다. 이 경우 새로고침 후에는 그 세트의 목표값이 다시 표시된다.
- 운동 리셋 판단(`hasResettableRecord`)에서 목표값과 같은 초기값은 "기록 없음"으로 본다.

### 9.3 세션 상태

| 상태 | 의미 |
|---|---|
| NOT_STARTED | 시작 전 |
| IN_PROGRESS | 진행 중 |
| PAUSED | 일시 중단 |
| COMPLETED | 완료 |
| ABANDONED | 중도 종료 |

중도 종료된 기록도 보존하고 재개 가능 여부를 구분한다.

**완료와 중도 종료의 구분 (U-21 확정, v1.11):**

| 상태 | 전환 조건 | 증량 |
|---|---|---|
| COMPLETED | 세션의 **모든 예정 세트**가 완료(`completed = true`)된 경우에만 허용. 미완료 세트가 하나라도 있으면 완료 요청을 거부한다(`SESSION_HAS_INCOMPLETE_SETS`) | 완료 시점에 판정 (T3 FST-7) |
| ABANDONED | 사용자가 세션을 중간에 끝내는 경우. 완료와 별도의 작업으로 처리한다(구현은 후속 단계) | 판정하지 않음. 미완료 세션에는 T3 자동 증량을 적용하지 않는다 |

중도 종료 세션의 재개·리셋 정책은 U-15로 계속 관리한다.

하루 세션 상태와 별도로, 세션 안의 운동(SessionExercise)은 NOT_STARTED / IN_PROGRESS / COMPLETED 진행 상태를 가진다. 이 상태는 소속 세트의 완료 여부(없음 / 일부 / 전부)로 계산할 수 있다. 운동별 리셋은 하루 세션 상태를 변경하지 않는다.

### 9.4 운동별 전체 세트 리셋

기록을 다시 입력하려면 개별 세트를 수정하는 대신, 해당 운동(SessionExercise)의 **모든 세트**를 리셋하고 첫 세트부터 다시 입력한다. v1.2의 하루 세션 전체 리셋은 이 규칙으로 대체한다.

| 항목 | 규칙 |
|---|---|
| 리셋 단위 | 하루 세션 안의 운동 하나(SessionExercise)의 전체 세트. 세트 단위 부분 리셋은 제공하지 않는다 |
| 대상 식별 | `sessionExerciseId`로만 식별한다. `exerciseId`는 여러 세션에 존재하므로 식별자로 쓰지 않는다 |
| 허용 조건 | 하루 세션(WorkoutSession) 상태가 IN_PROGRESS 또는 PAUSED |
| 불허 조건 | COMPLETED — U-14 확정 전 불허 / ABANDONED — U-15 확정 전 불허 (CALCULATION_RULES) |
| 사용자 확인 | 확인 모달에서 명시적으로 승인한 경우에만 실행 |
| 초기화 대상 | 대상 운동의 모든 세트의 체크 상태(`completed`), `completedAt`, `actualWeight`, `actualReps` |
| 진행 상태 | 모든 세트가 미완료가 되므로 현재 세트는 첫 세트로 계산된다. 운동 상태를 저장하는 경우 NOT_STARTED로 재설정 |
| 리셋 이력 | 대상 운동의 `resetCount` 1 증가, `lastResetAt` 갱신 |
| 보존 대상 | `targetWeight`, `targetReps`, `setNumber`, 운동의 템플릿 ID·버전, 세션 시작 시점 TM(또는 T3 작업 중량)·증가 단위 스냅샷 |
| 변경 금지 | 같은 세션의 다른 운동 기록, 하루 세션 상태, 운동 프로필(`currentTM` 등), TM 변경 이력, T3 다음 목표 작업 중량 |
| TM·작업 중량 | 리셋으로 새로운 TM이나 작업 중량을 생성하지 않는다 |
| 증량 | 자동 증량은 하루 세션 완료 시 판정하므로, 리셋 가능한 세션에는 확정된 증량이 없다. 리셋은 증량 이벤트를 만들지 않는다 |
| 휴식 타이머 | 대상 운동의 타이머가 실행 중이면 중지 |
| 원자성 | 하나의 쓰기 트랜잭션에서 전부 성공 또는 전부 롤백 (TECHSTACK 5.4) |

**저장 계층 구분:** 일반 세트 수정 요청은 완료된 세트에 대해 거부한다. 승인된 운동별 리셋은 별도의 리셋 작업(`resetSessionExercise()`)으로만 수행하며, 일반 세트 수정 경로로 완료 세트를 초기화할 수 없다.

### 9.5 운동별 리셋 흐름

1. 사용자가 진행 중인 운동(T1/T2/T3 중 하나)에서 리셋을 선택한다.
2. 확인 모달에 대상 운동과 초기화될 세트 수를 표시한다.
3. 취소하면 아무것도 변경하지 않는다.
4. 승인하면 `resetSessionExercise(sessionExerciseId)`를 호출한다.
5. 저장 계층이 트랜잭션 안에서 하루 세션 상태를 다시 확인한다.
6. 대상 운동의 세트 실제값·완료 상태, 진행 위치, 리셋 이력을 갱신한다.
7. 화면은 대상 운동의 첫 세트 입력 상태로 돌아간다.

## 10. FR-008 — 로컬 데이터 저장

**우선순위:** P0

### 10.1 기본 정책

MVP는 회원가입 없이 브라우저에 데이터를 저장한다.

최종 저장 기술은 개발 단계에서 결정하되, 운동 기록과 설정 데이터를 구조화하여 관리한다.

### 10.2 저장 대상

- 주간 프로그램 설정
- 운동별 1RM
- 운동별 initialTM·currentTM (동일 exerciseId는 T1·T2 공통)
- TM 변경 이력
- 세션 시작 시점의 TM·템플릿 버전·목표 중량 스냅샷
- 세션별 운동 실행 단위(SessionExercise)의 진행 상태와 리셋 이력
- T3 작업 중량
- 운동별 중량 단위
- T2·T3 변경 운동
- 휴식 시간 설정
- 운동 세션 기록
- 다음 운동 목표 중량

### 10.3 저장 정책

- 운동 중 기록이 변경되면 저장한다.
- 새로고침 후에도 진행 기록을 복원한다.
- 이전 기록을 새로운 목표값으로 덮어쓰지 않는다.
- 데이터 형식 버전을 관리한다.
- 브라우저 데이터 삭제 시 기록이 사라질 수 있음을 안내한다.
- 저장 오류가 발생하면 사용자에게 표시한다.

### 10.3.1 저장 계층 구현 (STEP 09, v1.10)

Dexie + IndexedDB로 구현했다(`src/storage/`). UI는 아직 연결하지 않았다.

| 함수 (`src/storage/repositories/`) | 역할 | 주요 실패 코드 |
|---|---|---|
| `saveExercise()` / `getExercise()` | 운동 마스터 저장·조회 | `INVALID_INCREMENT`, `UNIT_CHANGE_NOT_ALLOWED`(프로필이 있는 운동의 단위 변경) |
| `initializeExerciseProfile()` | Setup 확정 시 프로필 최초 생성 + INITIAL TM 이력 (한 트랜잭션) | `PROFILE_ALREADY_EXISTS`, `UNIT_MISMATCH`, `INVALID_SOURCE` |
| `getExerciseProfile()` / `updateT3WorkingWeight()` | 프로필 조회, T3 작업 중량 직접 수정 (변경 번호 +1) | `PROFILE_NOT_FOUND`, `UNIT_MISMATCH` |
| `applyTMChange()` / `listTMChanges()` | 계산된 TM 변경을 이력과 함께 기록, 이력 조회 | `SESSION_NOT_COMPLETED`, `DUPLICATE_PROGRESSION` |
| `startWorkoutSession()` | 하루 세션 시작(IN_PROGRESS)과 스냅샷 고정, 계획 순서대로 `displayOrder` 저장, T3 FST-7 세트 생성 | `ACTIVE_SESSION_EXISTS`, `MISSING_SNAPSHOT_VALUE`, `INVALID_SESSION_PLAN` |
| `getLastCompletedSession()` | 완료 시각이 가장 늦은 COMPLETED 세션 (다음 운동일 기본 선택, v1.15) | — |
| `getActiveSession()` / `getSessionDetail()` | 새로고침·재시작 후 진행 기록 복원 (12.1의 `restoreWorkoutSession()` 역할). 운동은 `displayOrder` 순 | — |
| `updateSetDraft()` | 미완료 세트의 입력 중 값 저장 | `SET_LOCKED`, `SESSION_NOT_EDITABLE`, `INVALID_ACTUAL_*` |
| `completeSet()` | 세트 완료 트랜잭션, 휴식 타이머 시작 신호 반환 | `SET_ALREADY_COMPLETED`, `SESSION_NOT_EDITABLE`, `INVALID_ACTUAL_*` |
| `resetSessionExercise()` | 운동별 전체 세트 리셋 | `RESET_NOT_ALLOWED`, `SESSION_EXERCISE_NOT_FOUND` |
| `completeWorkoutSession()` | 하루 세션 완료 + T3 FST-7 증량 판정·반영 | `SESSION_HAS_INCOMPLETE_SETS`(U-21), `SESSION_NOT_IN_PROGRESS` |
| `saveInitialSetup()` / `getSavedSetup()` | Setup 확정값(운동 14개·프로필·INITIAL TM 이력)을 한 트랜잭션으로 저장, 저장된 설정 조회 (STEP 10 추가) | `SETUP_ALREADY_EXISTS`, `INVALID_SETUP` + 개별 검증 오류 |
| `addSetupExercises()` | 저장된 설정에 새로 확정된 운동(스모 데드리프트)만 추가. 기존 데이터 불변 (v1.13) | `SETUP_NOT_FOUND`, `PROFILE_ALREADY_EXISTS` |

- 모든 함수는 예외 대신 `{ ok: true, value }` / `{ ok: false, error, message? }`를 돌려준다. IndexedDB 자체 오류는 `STORAGE_ERROR`다.
- UI는 저장 결과가 `ok`일 때만 완료로 표시한다(낙관적 완료 표시 금지).
- 진행 중(IN_PROGRESS·PAUSED) 세션은 한 번에 하나다. 여러 탭에서 동시에 같은 작업을 해도 트랜잭션 안의 재확인으로 하나만 성공한다.
- T1·T2 목표 세트는 호출자가 계산해 넘긴다(템플릿 미확정). 세션 완료 시 T1·T2는 증량 판정 없이 `pendingProgressions`로만 돌려준다.
- 세트 입력·완료는 IN_PROGRESS에서만, 리셋은 IN_PROGRESS·PAUSED에서만 허용한다. 일시정지·재개·중도 종료(ABANDONED) 함수는 아직 없다(후속 단계).
- 세션 완료는 모든 예정 세트가 완료되어야 한다(U-21). 거부되면 세션·세트·프로필 어느 것도 바뀌지 않는다.
- 세션 도중 사용자가 T3 작업 중량을 바꿨다면 자동 증량으로 덮어쓰지 않고 사용자 값을 유지한다(U-22, `skippedReason: "PROFILE_CHANGED"`). 세션 시작 스냅샷과 완료 세트 기록은 어느 경우에도 바뀌지 않는다.
- 완료 세트는 `resetSessionExercise()`를 통한 정상 리셋으로만 초기화된다. 직접 테이블 쓰기(update·put·delete·clear 등)는 저장 계층에서 거부한다. 단, 사용자가 브라우저 개발자 도구로 로컬 DB를 직접 조작하는 것까지 막지는 못한다(DATAMODEL 5장).

### 10.3.2 화면 연동 (v1.12 STEP 10 Lite → v1.14 전체 세션)

| 경로 | 동작 |
|---|---|
| `/setup` | 4단계 Setup 입력 → 확정 시 `saveInitialSetup`. 저장 성공 후에만 완료 화면. 실패 시 입력 유지·재시도. 저장된 설정이 있으면 읽기 전용으로 복원(덮어쓰기 금지, U-05) |
| `/workout` | 저장된 설정 확인 → 진행 중 세션이 있으면 `getActiveSession`으로 복원, 없으면 운동 시작 패널(Day 1~5 — 지난 운동의 다음 Day 기본 선택, T1·T2 TM과 목표 범위, T3 작업 중량, 티어별 휴식 시간) |
| `/prototype/*` | 저장하지 않는 디자인 Mock (기존 유지) |

- **전체 세션 (v1.14):** 선택한 요일의 T1(Hybrid T1, 9세트) → T2(Hybrid T2, 8세트) → T3(FST-7, 7세트), 총 24세트. 세션 계획에는 템플릿만 넘기고, 저장 계층(`startWorkoutSession`)이 같은 트랜잭션에서 TM 스냅샷으로 목표 중량을 계산한다. 화면은 T1을 먼저 펼치고 운동 간 자유롭게 전환한다. 화면에 "Hybrid 자체 템플릿 (원본 nSuns 공식 템플릿 아님)"을 표시한다.
- **이전 T3 전용 세션:** STEP 10 Lite에서 만든 세션은 그대로 보존한다. 진행 중이면 T1·T2를 추가하지 않고 T3만 이어서 완료하며(이전 휴식 시간 스냅샷 유지), 다음 세션부터 전체 세션이 된다.
- **증량:** 세션 완료 시 T3 FST-7(H-10)과 T1·T2 목표 달성 기반 TM 증량(H-22)을 같은 트랜잭션에서 판정·반영한다. 완료 결과 창에 운동별 목표 달성 여부, 이전 TM → 다음 TM 또는 "목표 미달 — 다음 운동 중량 유지"와 사유를 표시한다. 증량값이 없는 운동은 `pendingProgressions`로 돌려주고 TM을 유지한다.
- **세트 완료:** 화면 검증(`validateSetCompletion`) → `completeSet` → 저장 성공 후에만 완료·잠금·휴식 타이머. 실패 시 미완료 유지·입력값 보존·재시도. 같은 세트 연속 탭은 화면(진행 중 요청 추적)과 저장 계층에서 이중으로 막는다. 다른 탭에서 먼저 완료된 경우 저장소 기준으로 다시 불러와 안내한다.
- **세션 완료:** 모든 세트 완료 전에는 버튼 비활성(H-17). 완료 시 FST-7 결과(증가·유지·사용자 수정 유지)를 표시한다.
- **휴식 타이머:** 기본 T1·T2·T3 60초(티어별 사용자 변경 가능, 기기 localStorage 저장, 사용자 값 우선), 종료 예정 시각 기준 계산, 새로고침 후 복원, Vibration API 지원 브라우저에서만 진동, 알림음 없음.
- **실제값 입력 (v1.17):** 9.2.2절 — 목표값 프리필, ± 스테퍼(kg 2.5 / 반복 1), 미완료 입력값 Dexie 저장·복원.
- **미구현:** 세트 완료 전 목표 중량 수정 화면, 일시정지·중도 종료, 설정 수정, 증가 단위 수정, T2 운동 교체.

## 11. 데이터 모델

> **v1.8:** 확정 타입은 `docs/architecture/DATAMODEL.md`와 `src/domain/types/model.ts`를 따른다. TypeScript와 저장 모델(Dexie) 모두 필드 이름은 **camelCase**로 확정한다. 아래 JSON은 확정 타입에 맞춘 예시다.

### 11.1 Exercise (운동 마스터)

운동 이름·장비·중량 단위·증가 단위처럼 사용자 기록과 무관한 정보다.

```json
{
  "exerciseId": "bench_press",
  "name": "벤치프레스",
  "equipment": "BARBELL",
  "weightUnit": "kg",
  "increment": 2.5,
  "updatedAt": "2026-10-20T00:00:00.000Z"
}
```

덤벨 중량은 모든 덤벨 운동에서 한 손 기준으로 확정(U-19)되었으므로, 운동별 표기 기준 필드(구 `weight_display_mode`)를 두지 않는다. `equipment: "DUMBBELL"`인 운동의 모든 중량 값은 한 손 기준이다.

### 11.2 ExerciseProfile (사용자 기준 중량)

```json
{
  "exerciseId": "bench_press",
  "weightUnit": "kg",
  "oneRepMax": 100,
  "oneRepMaxSource": "DIRECT",
  "estimateRuleId": null,
  "initialTM": 90,
  "currentTM": 90,
  "t3WorkingWeight": null,
  "t3WorkingWeightRevision": 0,
  "updatedAt": "2026-10-20T00:00:00.000Z"
}
```

- `initialTM`은 `oneRepMax × 0.9`로 재계산 가능한 파생값이다. `currentTM`은 AMRAP 증량 이후 1RM에서 재계산할 수 없으므로 독립 저장값으로 관리한다.
- 프로필은 exerciseId당 하나이며, T1과 T2에서 같은 운동을 쓰면 같은 프로필을 참조한다.
- `t3WorkingWeightRevision`은 T3 작업 중량이 바뀔 때마다 1씩 오르는 변경 번호다(v1.11 추가, 사용자 수정·자동 증량 모두). 같은 값을 다시 저장해도 오른다.
- `weightUnit`은 프로필 값들의 단위이며 Exercise의 `weightUnit`과 같아야 한다.
- `oneRepMaxSource: "DIRECT"`는 사용자가 1RM을 **직접 입력**했다는 뜻이며, 실제 측정이 검증되었다는 뜻이 아니다.

### 11.3 SetRecord

각 세트는 하나의 SessionExercise에 소속된다.

```json
{
  "setRecordId": "session_001_t1_bench_press#1",
  "sessionExerciseId": "session_001_t1_bench_press",
  "sessionId": "session_001",
  "exerciseId": "bench_press",
  "tier": "T1",
  "setNumber": 1,
  "weightUnit": "kg",
  "targetWeight": 67.5,
  "targetReps": 5,
  "isAmrap": false,
  "manualTargetWeight": null,
  "completed": true,
  "actualWeight": 67.5,
  "actualReps": 5,
  "completedAt": "2026-10-20T09:10:00.000Z"
}
```

위 예시는 데이터 구조 설명용이며 특정 원본 nSuns 템플릿의 검증된 세트값을 의미하지 않는다.

### 11.4 WorkoutSession

```json
{
  "sessionId": "session_001",
  "scheduledDay": "MONDAY",
  "workoutDate": "2026-10-20",
  "status": "IN_PROGRESS",
  "startedAt": "2026-10-20T09:00:00.000Z",
  "completedAt": null,
  "schemaVersion": 1
}
```

날짜는 실제 수행 날짜와 예정 요일을 분리해 저장한다.

세션 시작 시 운동별로 적용 TM(또는 T3 작업 중량), 템플릿 ID·버전, 증가 단위, 세트별 목표 중량·반복을 스냅샷으로 저장한다. 운동별 스냅샷은 SessionExercise에, 세트별 목표값은 SetRecord에 둔다. 이후 프로필이 바뀌어도 이미 시작한 세션의 스냅샷은 변경하지 않는다.

### 11.4.1 SessionExercise

하루 세션에 포함된 운동 하나의 실행 단위다. 운동 마스터(Exercise)·사용자 기준 중량(ExerciseProfile)과 다른 개념이다.

```json
{
  "sessionExerciseId": "session_001_t2_ohp",
  "sessionId": "session_001",
  "exerciseId": "ohp",
  "tier": "T2",
  "weightUnit": "kg",
  "increment": 2.5,
  "templateId": null,
  "templateVersion": null,
  "tmAtSession": 50,
  "workingWeightAtSession": null,
  "workingWeightRevisionAtSession": null,
  "displayOrder": 1,
  "restSeconds": 120,
  "resetCount": 0,
  "lastResetAt": null,
  "progressionEvaluatedAt": null
}
```

- `sessionExerciseId`는 전역에서 유일하다. 같은 `exerciseId`가 여러 세션에 존재할 수 있다.
- 한 세션 안에서 `(sessionId, exerciseId, tier)` 조합은 하나만 존재한다. 이 조합은 기존 증량 멱등성 키와 1:1로 대응한다.
- `tmAtSession`은 T1·T2, `workingWeightAtSession`은 T3에서 사용한다.
- 현재 세트 위치(`currentSetIndex`)와 운동 진행 상태는 저장하지 않는다. 소속 세트의 완료 여부로 계산한다. 저장값과 실제 세트 상태가 어긋나는 문제를 막기 위함이다.
- `displayOrder`는 세션 안 표시 순서(0부터)다(v1.11 추가). 세션 생성 시 계획 순서대로 저장하고, 조회는 ID 문자열이 아닌 이 값으로 정렬한다. 같은 세션 안에서 유일하다.
- `workingWeightRevisionAtSession`은 T3 세션 시작 시점의 프로필 `t3WorkingWeightRevision`이다(v1.11 추가). 세션 완료 시 프로필 번호와 같을 때만 자동 증량을 반영한다(U-22).
- 같은 세션에 같은 운동을 다른 티어로 넣는 것(예: T1·T2 모두 OHP)은 허용한다. 같은 운동·같은 티어를 두 번 넣는 계획은 거부한다.
- `progressionEvaluatedAt`은 하루 세션 완료 시 이 운동의 증량 판정을 마친 시각이다(v1.10 추가). 판정 규칙이 있는 운동(T3 FST-7, v1.16부터 H-22 증량값이 있는 T1·T2)만 기록하며, 값이 있으면 다시 판정하지 않는다.
- 실제 저장 ID 형식은 `${sessionId}:${tier}:${exerciseId}`다(DATAMODEL 6.1). 위 예시 ID는 설명용이다.
- 위 수치와 null 템플릿 값은 구조 설명용이며 검증된 템플릿·TM 값이 아니다.

### 11.5 TMChange

```json
{
  "tmChangeId": "tm_change_001",
  "exerciseId": "ohp",
  "weightUnit": "kg",
  "fromTM": 50,
  "toTM": "<fromTM + 승인된 증량값>",
  "reason": "AMRAP_PROGRESSION",
  "sourceSessionId": "session_005",
  "sourceTier": "T1",
  "ruleId": "amrap-progression",
  "ruleVersion": 1,
  "appliedAt": "2026-10-24T10:00:00.000Z"
}
```

`(sourceSessionId, exerciseId, sourceTier)` 조합으로 같은 세션의 증량이 중복 적용되지 않도록 한다.

위 수치는 구조 설명용 예시이며 확정된 AMRAP 증량값이 아니다.

### 11.6 수정 차단의 책임

타입의 `readonly`와 완료 세트 타입 구분은 **컴파일 시점** 제약이다. 저장된 데이터의 실제 수정 차단(완료 세트 수정 거부, 운동별 리셋만 허용, 완료·중도 종료 세션 리셋 거부)은 STEP 09에서 서비스 계층(repositories)·Dexie 테이블 훅·트랜잭션으로 구현했고 fake-indexeddb 테스트로 검증했다(DATAMODEL 5장).

## 12. 계산 엔진 요구사항

### 12.1 핵심 함수

| 함수 | 역할 |
|---|---|
| `calculateTM()` | 1RM → TM 계산 (**구현**, `src/domain/calculations/trainingMax.ts`) |
| `validateWeightInput()` | 중량 입력 검증 (**구현**) |
| `estimateInitialOneRM()` / `resolveInitialOneRepMaxes()` | 초기 1RM 추천값·출처 결정 (**구현**) |
| `roundToIncrement()` | 장비 단위 반올림 (**구현**, 단위 불일치 거부) |
| `calculateT1Sets()` | T1 목표 세트 생성 (**구현**: `calculateTemplateSets(HYBRID_T1_TEMPLATE, …)`, 세션 시작 트랜잭션에서 호출) |
| `calculateT2Sets()` | T2 목표 세트 생성 (**구현**: `calculateTemplateSets(HYBRID_T2_TEMPLATE, …)`) |
| `generateFST7Sets()` | 12회 × 7세트 생성 |
| `evaluateFST7Progress()` | FST-7 다음 중량 판단 (**구현**, 유지 사유 구분) |
| `evaluateT1Progress()` | T1 AMRAP 기반 진행 판단 |
| `replaceExercise()` | 종목 변경과 중량 재계산 |
| `saveWorkoutSession()` | 세션 기록 저장 (STEP 09에서 `startWorkoutSession()`·`completeWorkoutSession()`으로 나눠 **구현**) |
| `validateSetCompletion()` | 체크 시 실제 중량·반복 입력값 검증 (순수 함수). 미구현 — 현재는 `completeSet()`이 같은 규칙을 직접 검증 |
| `completeSet()` | 세트 완료 저장: 검증 통과 세트를 트랜잭션 안에서 미완료 재확인 후 완료·잠금 (**구현**, `src/storage/repositories/workoutRepository.ts`) |
| `getCurrentSetNumber()` | 완료되지 않은 첫 세트 계산 (순수 함수). 저장 계층 조회 결과의 `nextSetNumber`로 제공 |
| `resetSessionExercise()` | 운동 하나(sessionExerciseId)의 전체 세트 리셋 (하루 세션 상태 검증 후 원자적 처리). v1.2의 `resetWorkoutSession()`을 대체 (**구현**) |
| `restoreWorkoutSession()` | 진행 기록 복원 (`getActiveSession()`·`getSessionDetail()`로 **구현**) |

### 12.2 계산 엔진 원칙

- 계산 함수는 UI와 분리한다.
- 동일 입력은 동일 결과를 반환해야 한다.
- 검증되지 않은 템플릿으로 중량을 생성하지 않는다.
- 중량 계산에 부동소수점 오차가 누적되지 않도록 처리한다.
- 사용자 수동 수정값은 재계산 과정에서 임의로 삭제하지 않는다.
- 목표 중량과 실제 수행 중량을 구분한다.
- 자동 증량은 세션 단위로 한 번만 적용한다(중복 완료 이벤트 무시).
- 이미 시작한 세션은 시작 시점 스냅샷 기준으로 계산한다.
- 완료된 세트와 완료된 세션의 기록은 계산·저장 과정에서 변경하지 않는다.

조건: 진행 중 세션에서 운동 리셋 → 재입력 → 하루 세션 완료 (테스트 전용 증량 규칙) → 기대 결과: 해당 운동 증량은 한 번만 반영, 리셋 자체는 증량 이벤트를 만들지 않음

### TC-024 — 리셋 원자성

조건: 운동 리셋 처리 중 저장 실패 → 기대 결과: 대상 운동의 세트·진행 상태·리셋 이력 모두 리셋 전 상태 유지

### TC-025 — 체크 저장 성공

조건: 유효한 실제 중량·반복 입력 후 체크 → 기대 결과: 저장 성공 후 완료 표시·잠금, 다음 세트가 있으면 휴식 타이머 시작

### TC-026 — 체크 입력값 검증 실패

조건: 실제 반복 미입력 상태로 체크 → 기대 결과: 체크 거부, 미완료 유지, 저장하지 않음

### TC-027 — 체크 저장 실패

조건: 체크 중 저장 실패 → 기대 결과: 미완료 상태로 복귀, 입력값 보존, 타이머 미시작

### TC-028 — 완료 체크박스 해제 불가

조건: 완료된 세트의 체크 해제 시도 → 기대 결과: 거부, 완료 상태 유지

### TC-029 — 마지막 세트 체크

조건: 운동의 마지막 미완료 세트 체크 저장 성공 → 기대 결과: 휴식 타이머 자동 시작하지 않음

### TC-030 — 현재 세트 계산

조건: 1·2세트 완료, 3세트 미완료 → 기대 결과: 현재 세트 = 3세트 (저장된 위치값 없이 계산)

### TC-031 — Setup 4대 운동 1RM

조건: 벤치 100kg 입력 → 기대 결과: 초기 TM 90kg 표시, 0·음수·문자 입력 시 다음 단계 진행 불가

### TC-032 — Setup 추천값 재계산

조건: 추천값을 건드리지 않은 상태에서 백 스쿼트 1RM 변경 → 기대 결과: 프론트 스쿼트 추천값 재계산

### TC-033 — Setup 사용자 값 보존

조건: 추천값 확정 또는 수정 후 기준 1RM 변경 → 기대 결과: 확정·수정값 유지, 다른 운동 값 불변

### TC-034 — Setup T3 작업 중량

조건: T3 5개 운동 작업 중량 입력 → 기대 결과: 운동별 독립 값, 1RM·TM 미적용

세부 계산 테스트 명세는 `CALCULATION_RULES.md` 10장을 따른다.

## 17. 최종 기능 정의

nSuns Hybrid는 nSuns 기반 근력 훈련과 FST-7을 결합한 무료 운동 관리 서비스다.

T1·T2의 1RM을 입력하면 TM의 90% 기준을 활용하여 세트별 목표 중량을 자동 계산한다.

T2·T3 운동을 변경하더라도 각 운동에 저장된 기준 중량으로 자동 스케일링되며, T3는 항상 12회 × 7세트로 구성된다.

세트별 수행 기록과 휴식 타이머를 통합해 운동 과정을 관리하고, 수행 결과를 다음 훈련의 목표 중량에 반영한다.
