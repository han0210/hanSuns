## 1. 문서 목적

nSuns Hybrid의 핵심 계산 규칙을 단일 문서로 관리한다.

계산 엔진은 다음 기능을 담당한다.

1. T1/T2 Training Max(TM) 계산
2. 운동 유형별 세트 템플릿 적용
3. 운동 변경 시 자동 중량 스케일링
4. 운동별 중량 증가 단위에 맞춘 반올림
5. T1 AMRAP 기반 다음 훈련 TM 조정
6. T3 FST-7 수행 결과 기반 증량
7. 계산 결과와 과거 수행 기록의 일관성 유지

계산 엔진은 React, IndexedDB 및 UI 컴포넌트에 의존하지 않는 순수 TypeScript로 구현한다.

## 2. 계산 규칙의 구분

### 2.1 원본 nSuns 규칙

nSuns 원본을 기준으로 검증해야 하는 사항:

- T1 운동일별 세트 수, 반복 횟수, TM 비율
- T2 원본 세트 및 강도 비율
- 1+ AMRAP에 따른 TM 증량 기준
- 각 프로그램 변형의 차이

원본 자료와 검증 결과를 확인하기 전에는 수치를 운영 템플릿으로 등록하지 않는다.

### 2.2 nSuns Hybrid 자체 규칙

다음 사항은 프로젝트에서 결정한 변형 규칙이다.

- 주 5일 운동 구성
- 바벨 로우 T1 추가
- 바벨 로우에 일반 5/3/1 벤치형 템플릿 재사용
- T2 운동 유형별 템플릿 사용
- T2 운동마다 독립적인 TM 적용
- T3 FST-7 7세트 × 12회 고정
- 운동별 중량 증가 단위
- AMRAP 증량 범위 내 고정값 자동 적용

원본 nSuns 규칙과 Hybrid 변형 규칙을 구분하여 관리한다.

## 3. Training Max(TM)

### 3.1 초기 TM 계산

초기 TM은 입력된 1RM의 90%다.

```text
initialTM = input1RM × 0.90
```

예시:

```text
input1RM = 100kg
initialTM = 90kg
```

### 3.2 현재 TM 관리

자동 증량을 위해 다음 값을 분리한다.

| 필드 | 의미 |
|---|---|
| input1RM | 사용자가 입력한 기준 1RM |
| initialTM | 입력 1RM의 90% |
| currentTM | 현재 훈련에 적용할 TM |
| nextTM | 다음 훈련에 적용할 TM |
| increment | 운동별 설정된 증가 단위 |

최초 설정에서는 `currentTM = initialTM`이다.

이후 자동 증량이 발생하면 `currentTM`은 별도로 관리한다.

1RM을 수정했을 때 currentTM을 재설정할지 유지할지는 별도 정책으로 정의한다. 사용자 승인 없는 암묵적 초기화는 금지한다.

### 3.3 유효성 검사

- 1RM은 0보다 큰 유한한 숫자여야 한다.
- 입력 누락 시 계산을 실행하지 않는다.
- NaN, Infinity, 음수는 거부한다.
- TM은 내부 계산에서 원래 정밀도를 유지한다.
- 장비의 중량 증가 단위는 최종 세트 중량에 적용한다.

## 4. 중량 계산 및 반올림

### 4.1 세트별 중량 계산

```text
rawWeight = currentTM × intensityRatio

targetWeight = roundToIncrement(
    rawWeight,
    increment
)
```

`intensityRatio`는 검증된 세트 템플릿에서 가져온다.

### 4.2 반올림

중량 증가 단위는 운동별로 저장한다.

예시:

| 계산값 | 설정 단위 | 표시 중량 |
|---|---|---|
| 62kg | 2.5kg | 62.5kg |
| 63kg | 2.5kg | 62.5kg |
| 64kg | 2.5kg | 65kg |

반올림은 가장 가까운 사용 가능 중량을 기준으로 한다.

정확한 중간값에서는 양수 중량 기준 높은 쪽으로 반올림하는 정책을 **Hybrid 제안 규칙**으로 사용한다.

예:

```text
61.25kg → 62.5kg
increment = 2.5kg
```

이 중간값 정책은 구현 전 승인 대상이며, 부동소수점 오차를 고려해 테스트한다.

### 4.3 운동별 단위

- 바벨: 사용자 설정 증가 단위
- 덤벨: 한 손 기준 여부 명시
- 머신: 장비의 실제 중량 단계 반영
- 단위 변경 시 아직 시작하지 않은 목표 세트 재계산
- 과거 완료 기록은 재계산하지 않음

## 5. T1 계산 규칙

### 5.1 기본 구조

T1은 요일별 기본 운동이 고정된다.

| 요일 | T1 운동 | 템플릿 |
|---|---|---|
| 월 | 벤치프레스 | 검증 후 지정 |
| 화 | 데드리프트 | 검증 후 지정 |
| 목 | 스쿼트 | 검증 후 지정 |
| 금 | OHP | 검증 후 지정 |
| 토 | 바벨 로우 | 일반 5/3/1 벤치형 |

T1은 9세트 구성을 기본 후보로 사용하되, 정확한 반복 및 TM 강도 데이터는 기준 원본 스프레드시트 검증 후 확정한다.

### 5.2 템플릿 데이터 구조

각 세트는 다음 속성을 가진다.

```text
setNumber
targetReps
intensityRatio
isAmrap
restSeconds
```

각 템플릿은 별도의 ID와 버전을 보유한다.

### 5.3 바벨 로우 T1

**확정 결정: 일반 5/3/1 벤치형 템플릿 재사용**

바벨 로우는 다음 규칙을 따른다.

1. 바벨 로우 전용 1RM을 입력한다.
2. 독립적인 초기 TM을 계산한다.
3. 일반 5/3/1 벤치형의 세트·반복·강도 구조를 사용한다.
4. 실제 수행 중량과 반복 횟수를 독립적으로 저장한다.
5. 바벨 로우의 TM 증량 이력을 별도로 관리한다.

주의사항:

- 이는 원본 nSuns가 아닌 Hybrid 변형 규칙이다.
- 원본 템플릿 재사용이 바벨 로우에 최적의 훈련 강도를 보장하지 않는다.
- 바벨 로우의 AMRAP 적용과 고강도 세트 수행은 실제 훈련 검증 대상이다.

## 6. T1 AMRAP 자동 증량

### 6.1 기본 원칙

- AMRAP는 가능한 반복 횟수를 기록하는 세트다.
- 프로그램 진행을 위한 기준 AMRAP 세트를 명확히 지정한다.
- 원본 기준으로 1+ 세트를 진행 판단에 사용하는 방안을 채택한다.
- 후반부 AMRAP 세트는 별도로 기록하며 자동 증량 판정에 중복 사용하지 않는다.

### 6.2 자동 증량 정책

**결정: 원본에서 제시하는 증량 범위 내 고정값을 사용한다.**

검토 대상 범위:

| 기준 AMRAP 반복 | 검토 대상 증량 정책 |
|---|---|
| 0~1회 | TM 유지 |
| 2~3회 | +5lb 기준 |
| 4~5회 | +5~10lb 범위 |
| 6회 이상 | +10~15lb 범위 |

이 표는 이전 조사에서 정리된 기준이며, 기준 원본 자료 및 프로그램 버전과의 최종 대조가 필요하다.

**현재 고정 증량값은 미확정이다.**

운영 구현 전 다음 항목을 반드시 결정한다.

1. 4~5회 구간의 단일 증량값
2. 6회 이상 구간의 단일 증량값
3. lb → kg 변환 방식
4. 운동별 증량 단위에 맞춘 보정 방식
5. AMRAP 미수행·미완료 시 처리
6. 기록 수정 시 TM 재계산 정책

미확정 상태에서는 자동 증량을 실행하지 않는다.

### 6.3 TM 증량 적용 시점

증량은 세션 완료 후 다음 해당 운동 세션에 적용한다.

```text
nextTM = currentTM + approvedIncrease
```

동일 세션에서 계산된 기존 세트 중량은 변경하지 않는다.

같은 세션을 두 번 완료 처리하더라도 증량이 중복 적용되어서는 안 된다.

## 7. T2 자동 중량 스케일링

### 7.1 핵심 규칙

T2는 운동 종목 변경을 지원한다.

변경된 운동은 기존 운동의 1RM을 사용하지 않는다.

```text
selectedExercise
    ↓
해당 운동의 currentTM 조회
    ↓
지원하는 T2 템플릿 조회
    ↓
세트별 목표 중량 계산
    ↓
운동별 증가 단위 반올림
```

### 7.2 운동 유형별 템플릿

**확정 결정: 운동 유형별 지원 템플릿 사용**

운동별로 원본과 Hybrid 계산 규칙의 적용 적합성을 검증한다.

초기 분류 후보:

| 유형 | 운동 예시 | 상태 |
|---|---|---|
| 프레스형 | OHP, 인클라인 벤치프레스 | 비율 검증 필요 |
| 스쿼트형 | 프론트 스쿼트 | 비율 검증 필요 |
| 힙힌지형 | 스모 데드리프트 | 비율 검증 필요 |
| 기타 부하형 | 슈러그 | 적용 방식 추가 검토 |

위 유형은 설계 후보이며 강도 비율의 승인이나 지원 운동 확정을 의미하지 않는다.

각 유형의 템플릿은 다음 값을 가진다.

```text
templateId
templateVersion
exerciseType
supportedExerciseIds
sets[]
```

### 7.3 운동 교체 처리

1. 변경할 운동 선택
2. 운동의 지원 템플릿 확인
3. 해당 운동의 저장된 currentTM 조회
4. 없다면 1RM 최초 입력 요청
5. 세트별 중량 자동 계산
6. 사용자 확인 후 적용
7. 기존 운동 수행 기록 보존

지원 템플릿이 없는 운동은 임의의 강도 비율을 부여하지 않는다.

### 7.4 계산 예시

아래는 자동 스케일링 알고리즘 설명을 위한 가상 비율 예시다.

```text
Exercise A
TM = 70kg

Exercise B
TM = 80kg

Example Ratio = 0.75

A → 52.5kg
B → 60kg
```

75%는 승인된 T2 운영 템플릿이 아니며 구현 상수로 사용하지 않는다.

### 7.5 T2 증량 정책

운동별 currentTM은 독립적으로 유지한다.

T2의 자동 증량 조건은 아직 확정되지 않았다.

검증 및 승인 전에는 별도의 임의 증량 규칙을 적용하지 않는다.

## 8. T3 FST-7

### 8.1 고정 세트 구성

```text
sets = 7
targetReps = 12
totalTargetReps = 84
defaultRest = 30 seconds
```

T3는 1RM 또는 TM을 사용하지 않는다.

### 8.2 작업 중량

사용자가 운동별 작업 중량을 직접 입력한다.

해당 중량을 7개 세트의 기본 목표값으로 사용한다.

### 8.3 자동 증량 판정

다음 조건을 모두 충족해야 한다.

- 7세트 모두 완료
- 세트마다 실제 반복 횟수 12회 이상
- 모든 세트의 실제 사용 중량 확인
- 실제 수행 중량이 세션 기준 목표 작업 중량 이상

조건을 만족하면:

```text
nextWorkingWeight =
    currentWorkingWeight + increment
```

조건을 만족하지 않으면 현재 작업 중량을 유지한다.

### 8.4 증량 예시

```text
현재 작업 중량 = 15kg
설정 증가 단위 = 2kg

7세트 모두 성공
→ 다음 작업 중량 = 17kg

6세트 성공 + 1세트 미달
→ 다음 작업 중량 = 15kg
```

증량은 다음 세션에 적용하며 과거 기록은 변경하지 않는다.

### 8.5 T3 운동 변경

새 운동은 독립적인 작업 중량과 증량 이력을 사용한다.

기존 운동의 작업 중량을 새로운 운동에 자동 복사하지 않는다.

## 9. 데이터 일관성과 기록 보존

### 9.1 세션 스냅샷

운동 시작 시 다음 정보를 세션에 보존한다.

- 운동 ID 및 티어
- 적용 템플릿 ID와 버전
- 해당 세션에 적용한 TM 또는 작업 중량
- 목표 세트별 중량과 반복 횟수
- 운동별 증가 단위

운동 도중 사용자가 기본 설정을 변경해도 이미 완료된 과거 기록이 변경되어서는 안 된다.

### 9.2 자동 증량 중복 방지

동일 운동 세션의 완료 이벤트를 중복 처리하더라도 증량을 한 번만 반영해야 한다.

### 9.3 기록 수정

완료된 기록은 사용자가 수정할 수 있다.

다만 과거 기록 수정으로 인해 이미 시작된 후속 세션의 목표값을 암묵적으로 변경해서는 안 된다.

후속 세션에 미치는 영향은 별도의 승인된 재계산 정책으로 처리한다.

## 11. 구현 제한사항

Claude Code는 다음 규칙을 준수한다.

1. 검증되지 않은 nSuns 세트 비율을 임의 생성하지 않는다.
2. 미확정 AMRAP 증량값을 운영 로직에 넣지 않는다.
3. 운동 변경 시 다른 운동의 중량을 재사용하지 않는다.
4. 기존 완료 기록을 자동 계산값으로 덮어쓰지 않는다.
5. 계산 로직과 UI 및 Dexie 접근 코드를 분리한다.
6. 계산 규칙을 변경할 경우 테스트를 먼저 수정한다.
7. 승인 없이 프로그램 구성 또는 새로운 기능을 추가하지 않는다.
8. nSuns 원본 규칙과 Hybrid 변형 규칙을 명확히 구분한다.
